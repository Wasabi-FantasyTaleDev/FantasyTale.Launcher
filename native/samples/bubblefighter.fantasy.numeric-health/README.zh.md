# 数字血量（实验性）

[English](README.md)

0.2.10 默认使用印尼服原生位置、黄色字体、归一化血量并开启百分号。切换版本时保留已保存的选项覆盖。用户选择 0.2.9-rc.1 后，已在 x64 的 kr-812 实机客户端确认百分号及原生位置正常；此前 ARM64 未显示符号的问题尚未解决。实际 HP 是血量数值而非百分比，因此这一模式有意不显示百分号。

候选版 0.2.9-rc.1 将提供的百分号图片接在归一化 HP 数字后。`show_percent` 默认开启；
显示实际 HP 时不附加百分号。插件包含原始 20×18 PNG 和自行生成的单帧
SMF 描述，存放在 `assets/`。通过游戏资源管理器直接读取插件的绝对路径，
不替换游戏归档或客户端散文件。私有字符表将百分号对应到这一帧；原生文字
渲染器测量当前数字的实际宽度和缩放，再把图片接到右侧。格式化入口传入
`%%`，以显示字面的百分号。

激活前检查有大小上限的 PNG 文件头、尺寸和生成的 SMF 描述。素材缺失或
无效时，在注册补丁前拒绝激活。绘制时继续校验帧归属、数量、矩形和纹理；
资源尚未就绪时仅隐藏百分号，并记录有次数上限的诊断。本地激活需要配套的
`assets/` 目录；私有工作区中存在这些文件不代表已取得再分发权。经审查的公开
源码导出排除这些精灵素材；合成测试不需要私有图片，也不会生成可完整分发的插件包。
上述 x64 实机确认已经完成百分号和位置的候选版验收。
ARM64 实机日志已确认单帧纹理驻留，但用户仍未看到百分号。架构仅是需要
对照的变量，尚未确定是原因。候选版仅记录一次数字和符号的实测尺寸及
最终符号坐标；x64 对照测试使用相同素材和原生绘制路径。

0.2.8 默认使用印尼服 HP 圆环右上方的原生位置。id-1809 `sub_789AB0`
使用生命条锚点 +(125 - 7×数字位数, -101)，白色和黄色现在共用这套计算，
血量位数变化时保持右侧对齐。可选的自定义位置保留原有偏移控制及其值；
偏移仅在选择自定义位置时生效。该版本默认颜色为白色，用户已经在 kr-812
实机对局确认位置正确。本次位置修改不代表黄色纹理可见性已经解决。

多个版本共用一个插件 ID。运行时地址从 DLL 旁边的 `client-versions.toml`
读取，不再编译进 hook。文件中已为所有可见的非印尼版本记录测量研究行，
包括 kr-1256、tw-454，并将资源更新分别登记；但当前只有已测量的固定基址 kr-812 会被接受。
提交补丁前验证时间戳、打包/重建映像大小、HUD 调用字节、资源入口签名和最大血量入口。
kr-812 从 EDI 捕获选中角色，不把 HUD 索引容器当作角色。最大血量入口尚未就绪时，
在现有有界解包期限内重试。

正式支持的描述声明 `health_accessor_abi = "thiscall_f64"` 或 `"edi_field_f64"`。
EDI 方式传入玩家对象 + `health_field_offset`，保留 EDI 并取得浮点返回值。
`maximum_health_source = "vtable_f64"` 要求提供 `maximum_entry_rva`、`maximum_health_rva`
和 `maximum_vtable_slot`，后者是按四字节对齐、范围为 4..4096 的字节
偏移。当前韩服描述使用 356；绘制代码不再为所有版本固定使用该位置。`player_capture` 可以
选择保留的调用方 EDI、EBX 或 ESI（`caller_edi`、`caller_ebx`、`caller_esi`），
HUD 的第一个指针（`hud_owner`），或原参数之后保存的指针（`caller_stack`）。栈捕获必须
声明 `player_stack_offset`，从第一个原参数计算，按四字节对齐且位于 28..4096。
所选指针为空或不可读时拒绝额外绘制。正式支持的描述必须声明 `hud_register = "ebp"`、
`"ebx"` 或 `"edi"`；统一的 x86 转发桩在进入 C++ 前保存寄存器，并保留七个原参数槽。
`white_style_slot` 选择原生白字样式：早期版本为 5，已测量的 2019 版本和当前韩服为 6。
也可声明 `maximum_health_source = "player_field_f32"`，从玩家对象
加上 `maximum_health_field_offset` 的地址读取浮点最大 HP，此时不能再声明上述三个虚表字段。
字段偏移必须位于 1..65536；字段不可读、最大值非正数或非有限数时抑制额外绘制。
其他寄存器或读取函数 ABI 仍须单独证明拦截约定。受控 x86 测试
通过不同玩家寄存器、保存的栈槽和无效指针区分各条捕获路径，
不会因此启用研究版本。分发时必须同时提供配套的 DLL 和描述文件。

原生精灵布局也来自描述文件。正式支持的行必须提供 `native_style_slot`（18..30）、
`native_style_sprite_index`（位于所选 128 字符映射之后且小于 4096）、`sprite_frames_offset`、
`sprite_texture_offset` 和 `texture_resident_offset`。成员偏移须按四字节对齐并位于 4..4096，
纹理字段不能与两个帧列表指针重叠。私有字体表上限为 4096 个字。
当前 KR 行保留样式 22、精灵索引 3079 和偏移 120/136/144；较早的研究客户端可使用
样式 21、索引 2822 和偏移 48/60/72，无须修改 DLL。这不能替代各版本加载函数、字符串、
加载参数 ABI 的验证与实机验收。

描述文件还记录 `resource_string_abi`、`resource_string_inline_capacity` 和
`resource_options_size`。CN2011/CN2012 使用四字节引用计数字符串（`cow_wstring4`），
参数对象分别为 36/40 字节；字符串头位于字符数据之前，没有内联容量。这些加载器
不能接收借用的 24 字节字符串，在实现原生字符串构造与释放之前仍保持研究状态。
CN2013 和 KR2015 使用 `msvc_wstring24`，UTF-16 内联容量为 7，参数对象为 88 字节。
此前 CN2011 的 32 字节参数记录和所有版本字符串布局相同的判断有误。
各研究行仍需完整资源加载与绘制约定验收后才能启用。

CN 研究记录已区分浮点 HP 与整数除以 20 的原有 Life 生命次数；原有 Life 文本保留。
EDI HP 和字段最大值适配已通过受控 x86 测试，但 CN 玩家/坐标来源及资源约定尚未验收，
这些研究行仍不能加载。

0.2.5 恢复初版原生白色 slot-5 绘制与偏移 (80, -30)。黄色资源及延后 HUD
绘制实验未能稳定实现首次可见。初版白色方案曾验证满血和自伤更新；这次
恢复后的包仍需重新实机验收。保留原生命数、透明度和缩放，默认显示截断的
当前/最大 HP × 100，也可选择实际 HP。无效数据不追加绘制，仅记录一次；
首次绘制坐标、透明度及缩放也仅记录一次。

黄色数字曾在窗口变化后与临时白色对照同时出现，但后续测试即使纹理驻留、
底层绘制成功仍不可见。延后 HUD 绘制实验另有短暂撕裂反馈，因果尚未确定。
这些实验已撤出当前实现，ARM64 的黄色样式仍需继续排查。0.2.9-rc.1 使用提供的素材实现
独立百分比符号。插件不替换原有客户端资源；提供的图片能否再分发仍需单独审查来源与授权。

使用 Release|Win32 构建 numeric_health.vcxproj，将 numeric_health.dll、
`client-versions.toml`、plugin.toml、plugin-ui.toml、assets 目录放到导入目录。独立测试覆盖实际 x86 转发桩、实际/归一化数值、
无效数据、原绘制保留、映像拒绝和最大血量入口延迟就绪。合成测试不代表
实机显示成功；发布前需验证首次对局、复活、观战、模式倍率、缩放、离场/
重入及插件组合。变更需要重启游戏，不支持热卸载。

恢复版在等待后显示白色 71，用户反馈和截图均已确认。首次进入时立即显示
仍未解决，且原始白色路径也有这一现象。

0.2.6 添加可选的 `trace_timing`，默认关闭。每个进程最多记录七份快照：
距插件入口和首次拦截绘制的时间、调用次数、验证结果、位置、透明度、缩放、
当前/最大 HP。采样点是首次调用及其后 1/5/15/30/60/120 秒；错过的采样点
合并成当前一条。它只能证明提交情况，不能证明像素可见。重入对局不会
重新开始无限记录。
