# 商店来源

统一总目录规范与自建发布步骤见[自建商店源参考](self-hosted-store.zh.md)。

[English](store-sources.md)

商店将客户端与插件分成两个分类，资源列表旁边显示版本详情。只有列表和
详情内容区域滚动；标题、筛选栏与操作区域保持可见。来源管理支持添加、
编辑、禁用和移除来源，目录位置放在可展开的高级选项中。

服务端资源可以订阅 GitHub Releases，总目录仍放在 AList 或 HTTP。详见[订阅规范](self-hosted-store.zh.md#订阅-github-服务端发行版)。压缩包安装自动定位可执行文件根目录，不依赖固定的外层文件夹名称。

## 可发现的服务器 profile

schema-two 商店目录通过 `[[servers]]` 提供长期服务器：

```toml
[[servers]]
id = "Community_Server"
kind = "server"
game = "bubblefighter"
name = "Community"
api_url = "https://game.example/"
host = "game.example"
port = 10101
builds = ["kr-812"]
profile = "servers/Community_Server.toml"
```

`profile` 选填，路径相对于来源根目录。AList、HTTP 和 GitHub 共用同一下载抽象。
浏览、查看详情和收藏只读取目录信息；明确保存或选择后才下载 profile，使用与本地文件
相同的冲突检查导入。没有声明 profile 路径时，将目录中的内联信息转为同一种本地 TOML。
profile 的游戏、ID、API 及已声明连接地址必须与选中的目录条目一致。

profile 是完整的 `schema = 1` 文档，`[server]` 包含 `id`、`game`、`name`，
可选 `api_url`，成对的 `host`/`port`，`builds`、`bundled_instances` 和可选 `prefer_ip`。
可选 `[presentation]` 保存简略介绍 `summary`、完整介绍 `motd`、图标、展示图片、
显示开关和状态；其中 `summary_translations`、`motd_translations`、
`icon_url_translations`、`images_translations` 表保存各语言内容。
`[[client_policy_sources]]` 和 `[[client_policy_rules]]` 保存服务器的客户端策略。
[联机指南](multiplayer.zh.md)说明 ID、文件名和覆盖确认规则。远程 profile 不能引用
其他用户的本地图片，也不能声明内置 `icon_asset` 权限。AList 发布工具会自动包含目录中
明确引用的 profile 文件。将文件放到 `--input` 下声明的路径；即使目录文件位于子目录，
这些路径仍相对于来源根目录。未引用的 TOML 不会上传。只有服务器的目录无需添加占位软件包。

上传前，使用启动器自身的读取器验证：

```sh
dotnet run --project tools/publish-launcher -c Release -- --validate-catalog public/FantasyTale/source.toml --source-root public
```

命令会逐一检查引用文件的 ID、游戏、API 和游戏连接地址是否与目录一致，复用明确下载时的
校验。省略 `--source-root` 时，路径从目录文件所在文件夹解析。上传工具固定 profile 的原始
字节并记录远程公开文件的当前内容，先上传并通过匿名下载验证 profile，再发布目录。本地文件
变动或观察到的远程冲突会中止发布；写入目录前还会再次检查全部引用元数据。这不改变用户端
行为：浏览目录仍然不会下载或保存 profile 文件。

## 多个来源提供同一插件

来源筛选默认选择“全部来源”，按来源列表从上到下的顺序合并所有已启用的来源。
类型、游戏和插件 ID 相同的插件只显示一张卡片，多个来源提供时显示来源数量。
仅显示名称相同不会合并；单独选择某个来源后，只展示该来源提供的内容。

多个来源提供同一插件时，安装弹窗会显示“下载源”下拉框，默认选列表中的第一个
已启用来源，即使后面的来源提供了更新版本也不会自动切换。每个来源独立保留版本、
兼容信息和清单校验值；版本不同时，来源选项同时显示版本号，也可以单独选择当前
来源提供的其他版本。切换来源时优先保留相同版本，否则选择该来源的最新版本。
不兼容的客户端会从安装目标中取消勾选，不会自动勾选其他客户端。

“安装后立即启用”默认勾选。取消勾选时仅下载到插件库，保留现有客户端的插件设置；
只有勾选时才会为所选客户端启用插件。

打开弹窗时会保存本次候选内容。确认安装后固定来源的传输类型、地址、目录路径，
以及所选版本和清单校验值。来源地址被修改后需要刷新并重新确认，不会悄悄换源。

## 客户端安装选项

客户端确认弹窗与插件确认弹窗使用同样的软件包卡片。安装客户端前会列出必装和推荐插件：
必装项保持勾选，可选项允许取消。插件区域默认收起，展开后列表独立滚动。

如果版本声明了追加语言包，还会显示默认收起的“显示语言”区域，支持多选。
原生语言固定勾选，选择其他语言时会同时安装对应的语言包；只有原生语言的版本不显示该区域。
确认内容固定对应的客户端版本与服务器。插件与客户端可以同时下载，客户端可用后再完成插件启用。

## 当前实现

统一目录可通过 `tools/publish-store/compose_catalog.py` 在本地准备：将现有软件包目录与
客户端定义合并为一个 schema-two 文档。配置文件使用 `[[profiles]]`，每行填写
`definition = "path/to/build.toml"` 和 `revision = 1`；路径相对于配置文件。
客户端定义包含游戏及版本身份、登录策略、必装和推荐插件。现有软件包条目与未修改的
profile 会保留；修改定义必须提高 revision，重复身份或版本回退会在写入输出前被拒绝。

参数为 `--catalog existing-source.toml --config profiles.toml --output unified-source.toml`。
输出必须使用新路径。这只是本地准备，尚未执行发布：上传前须运行
`dotnet run --project tools/publish-launcher -c Release -- --validate-catalog unified-source.toml`
通过启动器读取器验证目录，并明确选择公开路径。目录和文件清单不再设定固定大小或条目数量上限。
以当前易读的定义格式为准，历史测试读取器的限制不影响目录或文件清单设计。

添加已有客户端时，可以选择外层的发行文件夹。启动器最多向下查找八层，找到唯一匹配版本的
客户端后记录实际目录；找到多个客户端时，会要求选择更具体的文件夹。未找到主程序不会创建
客户端记录。重复添加同一目录会复用原记录；旧记录误指向上层目录时，会在核对版本后修正，
不移动游戏文件。

桌面启动器将来源设置保存到 `<data-root>/sources/<id>.toml`。
内置 Fantasy Tale 来源来自 `Stores/default-source.toml`，使用
`http://archive-cn.600819.xyz:5244/`，并默认启用“优先 IP 访问”。此选项会先解析域名，连接到 IP；可在来源编辑器中单独关闭。旧版本保存的旧内置地址会迁移到新地址并启用此选项，
同时保留来源原有的启用或禁用状态。商店来源独立于账号服务器与已安装客户端。
移除来源不会删除已安装文件。来源名称只是展示标签，不代表经过认证的身份。

后端通过 AList 或 HTTP 读取公开目录，两者共用浏览、分组、搜索与元数据
校验模型。AList 使用 `POST /api/fs/get` 解析虚拟路径；HTTP 将同一路径映射到
配置的基础地址下。两者都使用 GET 获取元数据，不依赖 HEAD 成功。
AList 的 API 凭据不会附加到解析后的存储下载请求。当前来源管理界面配置
公开来源；私有来源的凭据存储尚待实现。

AList 文件解析遇到连接中断、请求超时，以及 HTTP 或 API 错误码 408、429、
500、502、503、504 时，会做最多四次尝试，依次等待 250、500、1000 毫秒。
取消操作会中断等待；登录拒绝、文件不存在和无效元数据仍会报错。
每次尝试有三十秒期限，同时覆盖响应头和元数据内容的读取；即使共用的文件下载客户端
设置为无限 HTTP 超时也会生效。重试不会放宽文件大小或校验和检查。

默认路径为 `FantasyTale/source.toml`。管理员在 AList 中提供
`/FantasyTale/source.toml` 后，用户只需填写基础 URL。已有目录结构可以使用
高级设置中的目录文件路径。HTTP 服务器或 API 可以在相同相对路径提供完全
相同的 TOML 文件。临时签名直链按需解析，不作为软件包的长期身份保存。

## 服务器推荐的客户端下载

`GET v1/catalog` 中的客户端预设可包含以下可选对象：

```json
"downloadSource": {
  "kind": "alist",
  "baseUrl": "https://downloads.example.invalid/",
  "catalogPath": "FantasyTale/source.toml",
  "packageId": "bubblefighter.cn-406"
}
```

`kind` 为 `http` 或 `alist`，两者使用相同的商店目录和安装流程。包必须属于
该服务器的游戏，且只对应预设指定的客户端版本。单个发布可以省略版本标签；
多个发布必须使用发布模式，并有唯一最高的正数修订号。来源地址不能包含
凭据、查询参数或片段，目录路径不能越出根目录。

查询不会保存来源或启动下载。添加客户端时显示包名称和来源地址，可关闭
下载选项。确认后固定来源和文件索引校验值；安装前重新查询，内容变化时
拒绝安装。明确安装后才保存普通来源，其身份绑定服务器 API 与分发地址，
以便后续更新和重启恢复沿用现有安装记录。不会自动恢复已禁用或已修改的
来源。这项推荐不能配置启动器自身更新。

服务器未提供推荐时，添加或导入客户端的方式保持不变。启动下载失败会保留
已创建的客户端；重试时重新显示推荐内容，并复用该客户端，不会重复创建。

## 目录格式 schema 1

```toml
schema = 1

[catalog]
id = "community"
name = { en = "Community catalog", zh-CN = "社区资源" }

[[packages]]
id = "bubblefighter.cn-279"
kind = "client"
game = "bubblefighter"
builds = ["cn-279"]
version = "0.1.5.005"
name = { en = "China 2011", zh-CN = "国服 2011" }
description = { en = "A separate client installation." }
publisher = "Community"
size = 1024
manifest = "releases/cn-279/0.1.5.005/manifest.toml"
manifest_sha256 = "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef"
```

发布时必须将示例大小和摘要替换为实际值。一个目录可以包含同一资源的多个
发行版本，由发布者按新到旧排列。资源身份为“本地来源 ID + 资源 ID”，其他
来源不能仅通过同名 ID 替换它。重复的资源 ID 与版本组合会被拒绝。
路径相对于来源根目录，而非目录文件的父目录。使用未经编码的路径段，不
允许目录穿越、URL、反斜线、百分号编码、查询参数或片段，允许空格与 Unicode。

资源类型包括 `client`、`plugin`、`runtime`、`launcher`、`server`，商店界面目前展示客户端
和插件。一个客户端发行版本只对应一个 build；插件可以列出兼容的 build，
实际兼容性仍以插件自身定义为准。客户端更新标签为可选项，与游戏原始版本号相互独立；
插件、运行库、服务端包和启动器版本使用 SemVer。本地化标题必须有英文项，描述
只按纯文本展示，不执行标记代码。

来源列表、目录和 AList 解析响应不再设定固定条目数量或字节上限。
目录请求最多四项并行，完整文档读取期限为 30 秒。无效格式版本、摘要、路径、重复版本和未知字段均明确报错。

## 下载与更新的边界

桌面商店的客户端发行版本现已支持“下载并安装”。可以选择匹配的现有客户端，
或指定新安装路径；名称留空时使用版本名称，已有目录需要确认。
主页和下载页显示同一批真实任务，包括总进度、单文件进度、速度、预计剩余时间，
以及暂停、继续、重试和取消。清单未包含的其他现有文件会保留。

插件包现在复用同一下载队列、HTTP/AList 传输、SHA-256 校验、重启记录和进度界面。
选择一个兼容的已有客户端后，插件安装到用户插件库，不改变客户端所选版本或启用状态。
已经支持 ZIP 分发，aria2 仍待完成。仅浏览目录不会安装或运行软件包。
普通商店来源不能自行取得更新启动器的权限。哈希用于校验内容是否与目录一致，
不能证明发布者身份。启动器自身更新使用独立配置的来源和外部更新程序，并执行健康确认
及回滚，不要求签名密钥流程；详见[启动器自身更新](launcher-updates.zh.md)。

内置 Fantasy Tale 来源默认连接 `http://archive-cn.600819.xyz:5244/`，仍可通过来源编辑器
修改。旧版本保存的空地址会使用此默认值，保留用户原来的启用或禁用选择。

## 插件文件清单

无需先添加客户端即可浏览插件库。每个游戏下的同一插件只显示一张卡片，卡片内的
插件版本选择保留旧版，方便回退。一个插件包可以通过兼容配置和内部版本分支支持
多个客户端 build。没有客户端时，下载、导入及启用操作保持禁用，插件库仍可查看和搜索。

插件使用相同的文件条目，但 `[release]` 使用 `builds = ["cn-406"]`，代替客户端的单个
`build`。游戏、插件标识、SemVer 版本、兼容版本列表、总大小和完整清单摘要必须与商店
目录一致。下载的 `plugin.toml` 必须声明相同的游戏、标识和版本，并支持所选客户端。
清单必须包含根目录的 `plugin.toml`。商店 ZIP 分发和
本地 ZIP 导入均已支持。

校验后的文件在任务专属目录组装，再次与完整清单比对，最后使用本地插件安装器一次性
提交完整版本。内置标识仍被保留；启用要求由游戏／客户端的 `client_policy_rules` 管理。来源记录与插件目录
在同一次移动中提交。进程中断后的重复提交，只有来源、摘要和安装内容全部相同才成功；
其他来源或修改后的内容不能覆盖同一版本。商店安装不会取消正在确认的本地导入预览。
清理已完成或取消的任务时会清理其私有暂存目录，保留已安装版本。

安装新插件版本需要用户操作，修改已有客户端所选版本仍在“插件”页单独确认。
“检查更新”会从已安装包的原始来源发现兼容发行版本，下载前再次核对该来源。
后台发现会在前端启动后及每 30 分钟检查一次，在“更新”设置里有独立开关，不下载或
启用插件。同一游戏和版本的客户端共享结果；页面读取缓存，不会发起网络检查。
每轮最多检查 256 个客户端，时限两分钟。手动结果会阻止旧后台检查覆盖，退出时
先取消并排空检查，再关闭传输资源。内置插件随启动器更新。下载的新版本不会自动启用。

某个游戏/版本组检查失败时，仅该组显示不含敏感信息的错误分类，并保留上次成功的后台
检查结果和时间；其他组继续检查。客户端切换版本后会丢弃旧版本组的缓存，后续检查成功
则清除错误。整轮检查仍受两分钟总时限约束。

切换版本的确认弹窗默认保留共有选项。新版本已删除的设置不会保留，其余值必须通过
新版本的选项规则校验后才能切换。不兼容的值会使切换失败，旧版本和设置保持不变。
关闭确认弹窗中的“保留共有设置”后，可明确使用新版本默认值。此操作只影响当前客户端；
下载插件包不会迁移设置或自动启用插件。

公开目录与清单读取遇到临时连接故障或 HTTP 408/429/500/502/503/504 时最多重试三次。
每次重新解析来源元数据，不转发 API 凭据，所有尝试共用 30 秒时限。
权限错误、无效路径、文档过大或声明大小不符会直接失败，不进行重试。

匿名发布验收会将“数字血量”和“ESC 提前离场”安装到独立插件库，核对清单、文件
哈希及来源记录，检查颜色和模式选项，再重复安装同一版本。可对公开 AList 来源运行：

```powershell
$env:FT_TEST_PLUGIN_ALIST_URL = 'https://files.example.org/'
dotnet test FantasyTale.Launcher.slnx -c Release --filter PublicStorePluginTests
```

可选的 `FT_TEST_PLUGIN_ADDRESS` 仅将来源域名的连接指向指定 IP，用于本地 DNS 排查。
测试不使用账号凭据，不打开启动器或游戏，不启用插件，也不执行原生代码。
分发成功不代表实际游戏中的行为或其他客户端版本兼容性已经验收。

发布顺序为：不可变文件、不可变且带摘要的发行清单，最后更新目录或频道引用。
两种来源已经接入同一个下载和事务安装流程。AList 在重试或继续时重新解析文件地址；
临时存储地址不会持久化。来源类型不会改变安装功能。

## 客户端文件清单 schema 1

```toml
schema = 1
[release]
id = "bubblefighter.cn-279"
game = "bubblefighter"
build = "cn-279"
version = "0.1.5.005"

[[files]]
path = "BubbleFighter.exe"
source_path = "releases/cn-279/0.1.5.005/BubbleFighter.exe"
size = 1024
sha256 = "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef"
```

请替换示例大小和摘要。目录的 `manifest_sha256` 覆盖文件清单原始字节，包括存在的 BOM。
发行标识与总文件大小必须匹配所选目录。`source_path` 相对于来源根目录，`path` 相对于
客户端安装目录。设备名称、目录穿越、不区分大小写的重复路径、文件与目录冲突、
重解析路径及启动器会话／元数据路径均拒绝。首次安装必须包含此版本的游戏可执行文件；已有可执行文件的客户端允许只更新资源文件。
当前只接受未压缩文件，不执行远程安装脚本。

清单、文件列表、发行版本大小、备份和保留任务记录不再设定固定数量或容量上限。
下载队列同时处理最多两项活动传输。HTTP 每次操作的无响应期限为 30 秒，
不限制整份文件的下载总时长。范围响应必须匹配偏移与总长度；返回完整 200 响应时
重新下载该文件。断点续传后仍校验整份文件的 SHA-256。

已校验内容在目标卷的 `.fantasytale-install` 内暂存。解析下载地址前，队列重新检查已有
暂存文件的大小与 SHA-256。匹配的内容可供多个目标路径或恢复后的任务复用，无需再次
请求文件信息或传输。校验不符时重新解析地址并下载；即使内容已全部暂存，来源被删除、
停用或更换地址仍会停止任务。安装与启动、删除共用客户端锁。
替换前先写入持久化记录，失败时恢复原文件；重试安装时会恢复已停止进程留下的中断事务。
发现外部修改时停止恢复并保留备份。存在事务记录时阻止启动游戏。
替换文件期间不能暂停或取消；退出启动器会等待安装完成，并取消网络传输。

安装记录包含来源与资源身份、可选更新标签、内容快照摘要和来源地址指纹。
任务原子保存于 `<data-root>/downloads`，不再设定固定数量或字节上限。
重启后原本活动的任务重新进入最多两项并发的队列，手动暂停的任务保持暂停。
记录保留校验过的原始索引字节，不保存临时下载地址或凭据。客户端目录改变、
来源被删除、停用或更换地址时停止恢复。损坏记录保留并明确报错。
中断的安装事务在下载前恢复。后续任务清理不用的暂存内容，成功安装清理本次暂存文件。

开发地址 `#/store?storePreview=1` 开启仅供界面评审的内存样例目录。大小和资源
数据均为测试样例，不代表已经发布。浏览器中对来源的修改只保存在内存；
桌面正常浏览使用持久化的来源设置和实际目录。

## 自动扫描目录与文件同步

“国服 2011 / 0.1.5.005”这样的游戏原始信息保留在 build 定义中，更新文件时不会修改。
更新标签可选。日常文件同步不需要递增版本号，也不需要手工列出本次修改的文件。

首次参照 `tools/publish-store/publish.example.toml` 配置各游戏的 build、文件目录和
显示名称即可。输出目录必须与输入目录分开。使用 Python 3.11 或更新版本运行：

```powershell
python tools/publish-store/publish_store.py --config D:/Store/publish.toml --watch 30
```

之后只需替换输入目录中的文件。程序自动扫描，根据已缓存的大小、时间和文件身份判断变化，
只重新计算和复制新增或改变的文件。商店目录和文件索引由程序生成，维护者不需要编辑。
新内容按 SHA-256 命名保存，完成后原子替换完整目录。没有变化时不重新发布目录，发布失败
保留之前的目录。旧内容继续供已开始的下载使用。发布不再设定人为存储配额；旧配置中的 `storage_gib` 仍可读取，但不再限制容量。清理旧快照属于维护操作，不会自动删除仍可能被下载任务引用的文件。
`--full-check` 可以跳过发布端缓存，重新校验所有输入文件。

将输出目录映射为 AList 虚拟根目录，或作为普通 HTTP 静态根目录。用户只需填写来源 URL，
两种方式均读取 `FantasyTale/source.toml`。无需额外商店 API，也不需要重新构建启动器。
扫描器运行在能够读取所维护游戏目录的电脑或服务器上，AList 负责存储和下载地址解析。
如果使用纯云盘挂载，需要让扫描器能读取输入文件，或者把生成的输出同步进挂载目录。
本工具不要求每种 AList 存储驱动都能返回文件摘要。

自动生成的客户端条目使用 `update_mode = "files"`，每个资源只有一个当前文件快照。
目录和文件索引中的 `version` 都可省略；填写时也只是显示标签，文件变化后不强制修改。
内容快照摘要变化即可发现更新，与游戏原始版本号无关。本阶段从服务器删除文件不会删除
客户端本地文件。仍支持另一种手工维护的不可变发行方式，即 `update_mode = "release"`
配合递增 `revision`，但自动扫描目录无需使用这种方式。

启动器初次校验未知文件，成功后缓存摘要、大小、创建时间和修改时间。后续更新中，
匹配缓存的文件跳过重新读取；远端摘要或本地元数据变化时重新检查。实际下载列表及其
总字节数、百分比和预计时间只计算缺失或变化的文件。下载完成后仍校验整份文件的 SHA-256。
元数据缓存用于检测日常改动，不能发现刻意保留大小和时间的修改或静默损坏。删除客户端的
`.fantasytale-install/file-cache.json` 可在下次安装时强制重新校验本地文件。
校验仍使用 SHA-256；性能提升来自避免重复读取大文件，而非强制改用 MD5。

设置里的“客户端更新”默认在启动时及运行期间每 30 分钟自动检查。“自动下载并安装”
独立设置，默认关闭，开启后会跳过正在运行的游戏。客户端页与设置页可以手动检查，
主页和客户端行提供更新入口。检查严格使用安装记录绑定的来源与资源，不会寻找其他
同名来源作为替代。更换来源地址时需要从商店明确重新选择客户端；旧版安装记录没有
地址指纹时也需要这一步。手动导入的客户端显示为本地客户端，不自动猜测更新来源。

## 客户端压缩包分发

客户端发行包可以使用 `format = "archive"`，默认仍是
`format = "files"`；服务端发行包当前仍使用逐文件模式。这里统一表示一种压缩包传输模式，`archive_format` 只负责选择
解码器，目前支持 `zip`、`7z` 和 `rar`。三种格式都使用同一套私有暂存、SHA-256
校验和事务安装流程。

压缩包可以由多个有序分卷组成。每个分卷在 `[[files]]` 中作为一个传输对象，并填写
从 1 开始的 `volume`。启动器会分别下载和校验每一卷，分别支持断点恢复，只有完整且
连续的分卷集合准备好以后才开始解压。ZIP 分卷、7z 的 `.001` 集合以及 RAR 分卷都
按同一个逻辑压缩包处理；缺失、重复或混用的分卷会在解压前拒绝。

客户端压缩包不再设定固定的分卷大小或总体积上限。上传工具分块读取匿名下载
并计算 hash，远端大小必须与已经校验的本地文件一致，不能仅凭存储提供方宣称的更大
体积扩大读取范围。目录索引、普通逐文件包和启动器便携压缩包同样不再设定这些固定发布上限。

可选的 `password` 字段可以直接提供发行者设置的压缩包密码。它不会写入诊断日志或普通
下载任务快照，但发行者提供的原始清单及安装器保留的清单副本仍包含此字段。这仅用于方便
分发，不用于保密。没有该字段而压缩包被加密时，启动器会在安装时要求用户输入；输入的密码
只保留给本次重试使用。压缩包默认不加密。只有对应解码器能够完成认证时，才接受加密的
ZIP（包括 WinZip AES）、7z 和 RAR；密码错误会在任何客户端文件提交前失败。

解压始终在私有暂存目录中进行。路径越界、链接、特殊文件、重复路径、大小写别名、
不完整分卷都会被拒绝；每个展开文件必须符合声明的大小和已验证的内容身份。解压后的文件先成为普通的已校验内容对象，再复用
逐文件发行包的备份、所有权、回滚和恢复日志。压缩包不会直接覆盖客户端活动目录。

客户端压缩包展开、恢复日志与文件检查缓存不再设定固定文件数、目录数或字节上限。
实际容量仍受可用存储空间及平台对文件大小、集合的表示范围影响。本地资源文件名
可以包含 `#` 或 `%`，安装路径不会把它们当作 URL 转义；下载来源路径仍使用
更严格的 URL 路径规则。

逐文件模式仍然是增量更新的首选，因为压缩包内部任何成员变化时，通常都必须重新下载
整个压缩对象。

## 插件 ZIP 分发

插件发布可在 `[release]` 中设置 `format = "zip"`，并用唯一一项 `[[files]]` 指向
`.zip` 文件。文件大小和 SHA-256 对应压缩包原始字节，目录中的 `size` 同样为下载大小。
其他发布身份字段仍为 `id`、`game`、`builds` 和 `version`。不填写 `format` 或填写
`files` 则保持逐文件格式。HTTP 和 AList 使用同一份规范和下载队列。

压缩包根目录或一层外部目录内必须有 `plugin.toml`。安装器先验证下载字节，再复用
本地导入器的 ZIP 校验和不可变安装流程，不再设定固定的压缩大小、展开大小或条目数量上限，拒绝链接、路径越界、设备名和歧义路径。重试已完成安装时，来源
收据和解压内容必须一致。本地导入预览独立保留；下载和安装不会自动启用插件或修改
客户端的插件选择。

## 服务端包发布

现有目录扫描发布工具支持在 `[[clients]]` 之外添加可选的 `[[servers]]`，也支持只发布
服务端包。填写 `id`、`game`、`builds`、`version`、`name`、`directory`，可选填写
`exclude`。`builds` 为非空、不重复的兼容客户端版本列表，`version` 为服务端包的
SemVer 标签，与游戏原始版本号无关。生成的目录使用 `kind = "server"` 和
`update_mode = "release"`，文件索引使用内容摘要命名。服务端索引的 `[release]`
使用 `builds`，客户端则使用单个 `build`；二者复用 `[[files]]`
及逐文件 SHA-256 校验。ZIP 分发格式仍只用于插件。

```toml
[[servers]]
id = "bubblefighter.server"
game = "bubblefighter"
builds = ["cn-406", "kr-1256"]
version = "2.25.0"
name = "Bubble Fighter server"
directory = "./server-package"
```

发布器复用内容文件与元数据缓存，后续扫描不重复读取未变化的服务端文件。服务端默认
排除本地配置覆盖、环境文件、常见 SQLite／数据库文件、日志和私钥容器。文件名排除
无法识别其他配置文件中嵌入的秘密；应发布包含配置占位符的干净分发目录，不要使用
线上运行目录或玩家存档目录。其他部署专用文件可加入排除规则。

商店的“服务端”分类通过客户端和插件共用的持久化下载队列安装服务端包，支持单文件／
总进度、暂停、重试和来源绑定。包保存在 `<数据目录>/server-packages/`，目录身份包含
本地来源标识、地址、包标识及文件索引摘要。新发行包使用独立目录，已有托管配置仍使用
之前选定的版本。清空下载记录或重启启动器不会删除已安装包记录；未完成事务不会出现在
已安装包选择列表中。包库不再设定固定发行目录数量上限。

本机托管配置弹窗列出与所选游戏／客户端版本兼容的已安装包，同时保留手工选择目录。
安装和托管使用同一个独占包锁：重新安装正在运行的同一发行包会失败且不修改它，停服后
可以重试。安装不同发行包不会替换正在运行的目录。玩家存档仍保存在独立的托管数据目录。
浏览或安装包不会自动启动服务端。完整 af95d321 分发包已通过本机 HTTP 和 AList 协议
测试源完成下载、安装、逐文件完整性比较、启动与 SQLite 账号重启检查。桌面交互及官方
远程 AList 部署仍需另外验收；官方目录也仍需要发布服务端包。

## 上传生成的目录到 AList

生成干净的发布目录后，安装 Python `requests` 并运行：

```powershell
# 在当前进程环境中设置 FT_ALIST_USERNAME 和 FT_ALIST_PASSWORD。
python tools/publish-store/upload_alist.py --input ./public --base-url https://files.example.org/
```

凭据只从环境读取。工具仅上传目录引用的索引及内容文件，不上传无关本地文件或发布缓存。
先检查本地哈希，再上传内容文件、索引，并通过 AList API 验证匿名下载字节；已有不可变
内容必须一致。最后才替换商店目录，且要求上传期间原目录的公开摘要没有变化，替换后
再检查匿名目录。摘要检查属于乐观并发检查，多个发布者仍需管理员协调。上传或 API
失败会明确报错，不会被当成空目录发布成功。部分内容可能留待重试，原目录继续生效。
必须配置可写的 AList 存储驱动；管理员认证成功不代表对应的上传链路可用。
上传器默认遵循环境代理。本地代理无法访问 API 或存储主机时，可以用 `--no-proxy`
让本次上传进程直接连接，包括匿名内容校验；不会修改系统代理设置，也不会绕过认证、
哈希检查或最后才发布目录的顺序。

匿名校验会拒绝无效的元数据大小，响应超过声明大小时立即停止读取。
`--verify-timeout-seconds` 设置每个对象的流式校验总时限（30–3600 秒，默认 900 秒）；
单次阻塞读取另有 120 秒限制，避免持续少量返回数据使发布无限运行。
慢速连接上的大文件可适当增加时限。传输重试耗尽后不会发布目录。

`--workers` 支持 1–4，默认 2。传输并发有上限，全部内容传输完成后才传输索引；存储服务
限制并发上传会话时可使用 1。可选真实来源验收用例读取 `FT_TEST_ALIST_URL` 与
`FT_TEST_SERVER_PACKAGE`，匿名下载并比较完整分发目录，随后检查本机 SQLite、账号与票据
生命周期，不打开游戏窗口。

2026-10-09，此用例通过了已配置公网 AList 与完整 d66cc86a 服务端分发目录
（376 个文件）的验收。检查内容包括每个安装文件、注册与错误密码拒绝、启动票据签发、
房间目录加入与撤回、正常停止、持久账号重启，以及更换服务端包目录后保留同一本地存档。
这证明了后台安装与生命周期链路；真实客户端游玩、桌面自身更新替换和异地玩家连通性
仍需分别验收。

## 插件作者与上传者

插件包使用 `authors = ["Fantasy Tale Studio"]` 表示作者，与商店发布者分开。
插件发布工具从 `plugin.toml` 复制作者列表，当前内置插件的作者均为
Fantasy Tale Studio。商店目录另有可选字段 `uploader = "显示名称"`，用于
记录上传者，默认留空，未填写时界面不显示。当前发行暂不填写上传者；
后续可通过发布命令的 `--uploader` 参数指定。两个字段都是展示信息，
不代表身份认证，也不改变安装权限。不会为补充展示信息而重新发布已冻结的插件文件。
