# 账号等级数据

[English](levels.md)

游戏通过 `game.levels = "levels/levels.toml"` 声明等级数据。启动器读取该配置、原始或规范化 CSV 表，以及本地 PNG 图片。共享代码没有按游戏 ID 特判；这些内容只负责账号信息显示，不包含私有游戏模块或原生认证实现。

## 内置数据

| 游戏 | 普通等级编号 | 经验来源 | 图标 |
| --- | --- | --- | --- |
| 泡泡战士 | 1–240 | `levels.csv`，达到本级的累计最低 EXP | `rank.png`，5 列，23×26 像素格 |
| 跑跑飞空艇 | 1–30 | `levels.csv`，从原表上一行的 `nextRp` 转为本级最低 EXP | ASCII 文件名 `default-NNN.png`，可选 `star-NNN.png` |
| 超级跑跑 | 0–125 | 原始 `essenlevelinfo.txt`，仅 `fdLevelKind = 1` | `rankicon.png` 对应 0–97，`rankicon2.png` 从 98 接续 |

泡泡战士图集包含 260 个格子，提供的经验表只到 240 级；额外图标不代表已经有对应等级数据。名称暂缺，保留 `names_pending = true` 和 TODO。导入时将精确青色的分格背景转为透明，用户提供的原文件保持不变。

跑跑飞空艇原表有 30 行。第一行最低经验为 0，之后每行最低经验取前一行的 `nextRp`。星级图标作为这些等级的显示变体，不推测额外经验表；白色图标作为显式的未分级标识保留。安装后的所有图片文件名均为 ASCII，原韩文标签保留在 UTF-8 数据内容中。

超级跑跑原表混有多种类型，只读取游戏等级 `fdLevelKind = 1`。保留源编号：初始红色小鸡为 0、EXP 为 0，通过 `initial_level` / `initial_exp` 补足；原表第一行为 1、EXP 为 25。两张图属于同一条普通等级序列。第一张图的格子 98–100 不参与普通等级：问号在 99，小丑 Piero 在 100。两张图均为每行 9 格、每格 26×21 像素；尚无表行对应的额外图片内容保持闲置。

## 不修改源码更新

替换安装目录中游戏的 `levels/essenlevelinfo.txt`、`rankicon.png` 和 `rankicon2.png`，重新打开启动器即可。第二张图没有固定最高等级，保留原有网格布局时，新增的 kind-1 行会自动衔接。如果网格布局改变或增加第三张图，只需调整 `levels.toml` 的格子尺寸或增加 `[[atlases]]` 范围；新增图片时，为上一段补充明确的 `last_level`。BF/AR 也可以直接编辑数据表和图片，无需重新编译。自定义发行包还可让 `game.levels` 指向另一份等级配置。

`tools/import-level-assets.py --source <输入目录> --games <游戏目录>` 用 Python 与 Pillow 整理首次提供的素材；后续 TR 更新不需要运行该工具。Web 预览 JSON 只是开发快照，安装版启动器实际读取原表，不依赖该快照。

## 配置格式 schema 1

`[source]` 包含 `file`、可选 `encoding`（`utf-8`、`utf-16le`、`utf-16be`）、`skip_lines`、从 0 开始的 `level_column` 与 `exp_column`，以及可选的 `name_column`、成对出现的 `filter_column` / `filter_value`。支持 CSV 引号和双引号转义，跳过空行和 `//` 注释行。可用 `initial_level` / `initial_exp` 补足原表省略的初始等级。`display_offset` 默认为 0，只调整展示编号。经验值为进入本级的累计下限，包含边界值。

`optional_assets = true` 表示等级表和图片随发布包分发，不随源码仓库提供。设置该项后，如果等级表或任一引用的图片不存在，游戏照常加载，只是不显示等级；已存在的文件仍会完整校验，未设置该项的配置在缺少文件时仍会报错。内置配置都设置了该项，因为原始等级表和等级图标不在公开源码中，发布包中包含这些文件。

即使缺少资源，仍会校验配置类型、键、数值范围和本地路径，以及已存在的等级表和 PNG 头。跨资源关系（例如某个等级的矩形是否落在缺失图集内）只能在补齐资源后校验。访问被拒绝或文件位置被目录占用仍然报错，不视为可选资源缺失。

每个 `[[atlases]]` 指定 `file`、`first_level`、可选 `last_level`、可选 `first_cell`、`columns`、`cell_width`、`cell_height`、可选起点 `x` / `y`，以及可选 `variant`（默认 `default`）。独立图片使用 `[[icons]]`，指定 `level`、`file`、可选裁剪 `x` / `y` / `width` / `height` 与 `variant`。每个普通等级必须有默认图标。重复等级、重叠映射、非递增经验、越界路径和超出图片的矩形都会校验失败。

资源上限：配置 256 KiB，源表 4 MiB、16384 行，匹配等级 4096 个，图集 32 张，特殊图标 64 个，PNG 16 MiB、边长不超过 8192 像素。经验使用非负 64 位整数；桥接阈值以十进制字符串发送，前端使用 BigInt。未知数据不会猜测名称、图片或经验。

## 跟随服务器的账号及图标覆盖

账号属于当前选中的服务器。以服务器 `stats.level` 为准；缺失时可以通过 `stats.exp` 推导普通等级。显式但未知的等级保留数值，不能虚构图标；等级与经验不一致时不显示误导性的进度条。服务端提供的 HTTPS `levelIconUrl` 优先，否则使用内置等级图标。

`[[badges]]` 定义 `id`、`icon_id`、`name`、图片及可选裁剪。TR 配置如下：

| 标识 | 图标 ID | rankicon.png 内坐标 |
| --- | --- | --- |
| piero | 10000 | x=26、y=231、宽26、高21 |
| unknown | 10001 | x=0、y=231、宽26、高21 |

它们是显示覆盖，不是普通等级，也不赋予管理权限。服务端可以返回 `rankBadge: "piero"` 或 `levelIconId: 10000`，同时继续提供玩家正常的 `stats.level`、`stats.exp`。仅图标改变，正常经验和升级进度保留；`rankVariant: "star"` 可选择配置内的星级变体。清除覆盖后恢复普通图标。保留图标值不能与普通等级冲突。兼容旧服务把保留值直接放入 `stats.level` 的显示方式，此时若有 EXP，会据此计算底层普通等级。

账号页可显示原始等级名称，有一致的下一等级经验阈值时显示进度条。首页紧凑底栏只呈现图标、等级及服务端指定的统计字段，不增加设置行。
