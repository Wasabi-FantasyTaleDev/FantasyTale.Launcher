# 插件分发

[English](plugin-distribution.md)

文件替换和内存补丁从运行时 3.7.3、Launcher 0.1.68 起可声明 `client_languages` 和 `exclude_client_languages`。它们匹配所选**游戏语言**的完整标签，不区分大小写，与启动器界面语言无关。不写包含列表表示允许全部语言，再由排除列表过滤；重复或同时出现在两个列表的标签会报错。只有本次生效的文件参与目标冲突检查。为兼容两个解析器，同类 `[[files]]` 和 `[[patches]]` 声明各自连续排列。

使用 ZIP 格式的商店发布直接复用不可变的公开导入压缩包作为安装内容，仍校验大小与摘要，不再向另一个存储路径重复上传同一份 ZIP。

## 标识迁移与弃用

插件改名时，在 `[plugin].aliases` 中声明所有旧标识，例如
`aliases = ["example.first-name", "example.second-name"]`，同时提高插件版本并保持游戏归属。
发布工具把完整定义写入商店目录，让启动器在下载前就能通过旧标识找到新插件。
共享安装器不保存特定插件的改名表。再次改名时应保留全部历史别名；只有最终插件明确声明
取代中间标识、版本也更高时，才允许已安装的中间版本继续共存。无关的别名所有者及循环会被拒绝。

只有通过校验、兼容当前版本的新包已经安装后，才迁移选择。迁移保留启用状态和仍支持的选项，
同步处理服务端策略与已保存／导入的方案，不会启用中断的下载。正在运行的客户端继续使用当前会话；
延后升级仅在客户端空闲且用户没有再次修改相关选择时生效。原生清单读取器从运行时 3.7.2 起支持别名，
这些新包要求 Launcher 0.1.57 或更新版本。

弃用与改名分别处理。第二版商店目录可通过 `[[deprecated_plugins]]` 保留弃用记录，
字段为 `id`、`game`、多语言 `name` 和可选的多语言 `reason`；插件包下架后仍保留这些记录。
弃用版本不再作为商店商品提供。已启用的目录会移除该插件全部已安装版本和后续启动选择，
并以弹窗逐项展示插件信息卡片，说明文字位于卡片下方，同时从方案中移除该标识。
正在运行的会话使用的文件会保留到所有客户端释放占用；有下载进行时延后至后续目录检查处理。

弃用按插件标识和游戏归属匹配，不绑定原来的下载来源或安装凭据。
更改来源标识、地址，或从 ZIP 手动导入，都不会阻止已启用商店后续处理弃用。启动器自带文件不会被卸载。
改名标识不能同时声明弃用，以免丢失本应保留的设置。使用 `compose_catalog.py` 合入发布侧弃用数据前，
应先确保具备生命周期支持的启动器已经可公开下载安装；准备元数据本身不会修改线上商店。

Launcher 的 `games/BubbleFighter/plugins` 仅随包携带五个泡泡战士插件：Nirinsou Link、
诊断模式、游戏内叠加层、游戏控件调用支持、原生风格组件。游戏控件调用支持暂时保留原通知服务，
独立的原生调用提供者仍待实现。

`game.default_plugins` 明确逐项列出Nirinsou Link、游戏内叠加层、游戏控件调用支持及原生风格组件，
没有列入诊断模式，不存在“内置插件一律开启”的规则。新客户端会启用这四项中已经适配的插件。
已有的手动关闭选择继续保持关闭。不适配的默认插件不会生成选择，后续更新首次适配该客户端时，
由列表／启动检查补充并自动开启。仅下载可选插件不会成为自动启用的授权。

这五个插件同时声明商店管理及更新源，可以独立发现商店中的新版，无须同时更新 Launcher。
Launcher 自带更高版本时也会升级旧选择，保留启用状态与仍支持的选项。已安装的更高商店版本
不会被较旧的内置版本覆盖。商店安装仍校验固定清单、插件标识、文件大小和哈希。

其他可分发插件的编写目录为 `store-plugins/BubbleFighter`，不会进入 Host 的游戏文件复制范围，
也不会进入浏览器的内置插件列表。认证组件的来源归属由 `game.plugin_sources` 声明，启用和版本要求由各客户端的
`client_policy_rules` 声明。这些配置不含可执行文件，也不安装组件；用户通过正常的客户端安装／推荐流程明确下载。
KR1256 必选韩服认证与商店开放组件；国服版本必选国服认证组件。同一客户端范围内的必选与推荐规则不能重叠。

未完成的前进起跳插件保存在 `experimental-plugins/BubbleFighter`，不随包携带、不上架，
商店发布工具也拒绝发布这些标识。移动编写目录不会删除用户插件库、客户端文件、账号或设置。
修改本地插件资料及预览与发布到公开商店是两个独立步骤。

插件改名后的新版已公开可安装、且 `aliases` 声明了旧 ID 时，发布工具可使用
`--retire-aliases-for <当前ID>` 撤下旧 ID 对应的商店卡片。此操作读取已发布定义，
不依赖写死的改名清单；保留当前 ID 的全部历史版本供回退，不删除固定安装包，也不卸载用户已有选择。
旧 ID 归属冲突、循环引用或替代插件未覆盖旧版支持的客户端时会拒绝操作。
撤下旧卡片之前应先验证替代插件可以实际下载。
