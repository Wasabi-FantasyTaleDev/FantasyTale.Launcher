# 架构

带托管控制器的组件在控制器启动前取得稳定、按组件隔离的 Companion 通道，断线时
连接状态快照立即撤销本地权限。模式扩展先订阅事件，再获取初始创建房间上下文和
场景快照；只有上下文启用且场景为 `plaza` 时才观察原生控件，主菜单和房间内保持
休眠。重连会重新同步，不定时查询服务端，也不限制在广场等待的时长。排队中的
原生读取保留原操作标识，不再由控制器时限取消共享 Hook 管道；已受理的修改仍有
结果确认时限，结果不明确时不重放。

Overlay 插件可以声明游戏模块提供的后台控制器。宿主先启动控制器并订阅面板代理，
再发送入口 HTML；退出时先等待控制器清理完成，再关闭会话传输。原生窗口检测、
模式可用性判断及确认后的房间修改都在托管后台执行，WebView 休眠不影响这些工作。
页面接收带版本号的显示快照，发送绑定本次打开会话的用户操作；使用后台控制器的
面板不再接入前端原生控件调用接口。

Hook 通道占用与已提交操作的结果未知分开处理。尚未发送的请求可以在期限内重试，
已进入队列的操作只允许继续查询结果。模式观察也会等待原生 UI 短暂的就绪状态变化。
控制器的阶段、状态和原因记录写入独立的有界日志，避免被前端常规轮询冲掉启动故障证据。

自动选服准入与游戏原生连接收尾具有不同的生命周期。票据使用或授权到期时，通过带关联确认的刷新撤销候选，不发送 STOP。启动租约继续持有控制管道与已接入的连接，直到游戏完成收尾或关闭；只有显式销毁租约才取消其连接。

文件与内存插件按所选游戏语言匹配条件。文件先按版本及语言包含、排除规则筛选，再校验内容和目标冲突。两个解析器均拒绝重复或互相矛盾的标签，内存补丁使用相同的不区分大小写、完整标签匹配规则。

启动准备中的历史诊断清理是辅助操作。只处理确认属于启动器的诊断目录，先移动到清理名称再删除文件。目录被占用时尽可能保留，后续启动继续清理；清理失败记录路径、异常类型和系统错误码，不阻止创建本次诊断目录。日志根目录校验和本次诊断目录创建仍须成功。

插件组件恢复先检查只读快照，选择已是最新状态时直接返回，不申请客户端或名称注册锁。方案应用对没有变化的选择继续校验，但不保存。插件库没有清理候选时直接返回；对象关闭仅在需要丢弃待处理导入时取得库锁。实际清理在取得锁后重新读取候选再删除。实际修改仍申请原有跨进程独占锁，并在提交前重新校验。插件库存刷新可以推迟被占用的方案写入，保留选择供之后重试；启动仍等待方案应用。占用回复提供本地锁上下文供详情页展示，不包含凭据或推测的进程身份。

商店明确勾选“下载后启用”的选择覆盖所有兼容版本，包括未创建客户端配置的版本和缺失、关闭的
插件选择。前端将此选择保存在每个版本当前选用的方案中，切换版本时恢复方案不会覆盖宿主的启用
结果。未注册版本保留待解析选择，等共享插件包可用后应用。待启用记录绑定下载任务和原有选择；
取消下载时恢复尚未修改的选择，之后的手动修改优先。运行中的游戏退出后再应用。

归档成员替换方案可用 `when` 选择已有布尔选项，也可用 `when` 与 `when_value`
精确匹配声明的字符串或枚举选项。不同选项独立保存，新增样式无需新增资源提供器。
选项类型、枚举值及字符串长度在生成归档前校验；未匹配的选项不产生资源写入。

`when_options` 将多个已声明的布尔、字符串或枚举等值条件按 AND 组合，并与已有
`when` 条件共同生效。即使其他条件未匹配，也校验每个条件和当前选择值。
精确组合让同一归档成员对应多个独立设置，避免重复写入；场景行为仍由游戏包数据声明。

插件包校验并安装到共享库后，下载任务即完成。客户端配置应用独立持久化，其他插件缺失或未启用
不阻挡已验证插件的安装。开始游戏时仍检查完整配置。待应用提示和应用失败按当前客户端显示，
只有确实运行中的游戏才提示退出后生效。

外部 Overlay 只接受来自精确启动文档的 WebView 消息，包含所选主题及资源查询参数。
Hash 路由和本地子资源仍可使用；其他顶层文档和弹窗在导航前被阻止。修改就绪或输入状态前
先检查事件来源。这一检查不覆盖主 Photino 窗口，其原生来源及导航 API 仍在审查中。

插件包可以共享数据。`kind = "assets"` 的包只含数据，不会进入原生会话，任何包都可以声明 `requires`。
`PluginRequirements`（Core）为单个客户端解析这些依赖：启动时在改动客户端文件之前检查每个启用包的全部依赖，
商店安装路径则从同一目录排队安装缺失的依赖。启动 Overlay 时，Host 把已启用 Overlay 包及其依赖的数据包的
“ID 到文件夹”映射发送给 Overlay 进程（`package-roots`），由它通过 Sdk 中的 `OverlayPackageFiles` 自行应答
`https://packages.fantasytale.local/<id>/<path>`：只读，拒绝链接和越级路径，文件按流读取。详见
[共享数据包](plugin-management.zh.md#共享数据包与依赖)和[插件包文件](hook/overlay.zh.md#插件包文件)。

启动准备阶段拥有自己的截止时间，也受剩余自动选服授权期限约束。该取消令牌不能中断 Windows
系统确认窗口本身。如果系统已经创建进程后才发生取消或绑定失败，启动器会先把所有权交给正常
监控器，再报告启动失败。终止被拒绝时，运行记录、客户端租约及会话恢复屏障会保留到原进程句柄
确认退出，不会在子进程仍运行时恢复运行时文件。系统确认和真实客户端提权路径仍需独立的交互验收。

托管游戏模块与宿主共享 SDK 和可用的框架程序集，即使自带运行库的安装包在模块旁放置了框架 DLL，也不会重复加载。这保证宿主回调中的异常和序列化类型身份一致。其他托管与原生依赖仍按模块包隔离；宿主不存在的额外框架命名依赖仍可从模块包解析。

资源编辑提供方在冲突检查前将逻辑目标绑定到成员中的实际地址，原值条件在写入前统一只读检查。整成员与字段级选择共享绑定输入的快照；字段地址、成员与归档缓存均以原始资源为依据。游戏模块提供目标查询、清单构建器和原生控件检查，宿主传输结构化冲突报告及明确的重试选择。

临时 InfoBar 通知中的信息、成功和警告默认六秒后自动关闭，错误默认保留至用户关闭。调用方可显式指定长期显示或其他显示时长；鼠标悬停和键盘聚焦时暂停倒计时，同一操作的新通知重新计时。由持续状态控制的内嵌提示在对应状态仍存在时保持显示。

插件方案按客户端版本独立保存配置，并按服务器和版本记住选中的方案。应用方案保留已安装客户端记录，验证资源设置但不提前准备游戏文件。共享 TOML 由后端解析；尚未安装的选项保留在方案中，精确版本可用后再应用，不依赖导入弹窗保持打开。

私有单机服从主页开始游戏操作启动，保存设置不启动服务端，运行中修改需重启后生效。游戏退出、切换目的地和启动器退出时停止托管的私有进程。本机托管终端显示有界日志，只接受明确支持的服务端生命周期命令。

启动授权使用签发方同源期限，并映射到接收端的时间，按单调经过时间消耗。心跳健康状态由签发方判定；服务器明确在线且玩家端 TCP 测量成功时，不因观测时间戳或重复版本号排除节点。授权到期、明确离线或排空、容量已满及测量失败仍然生效。

原生目录保留所有配置的手动目的地，包括 DNS 或 TCP 测量失败的入口。不可用目标保留原身份和容量，由本机仅状态监听器提供原生状态，本次启动中不能重定向或成为活动自动候选；下次启动重新测量。目录不设置固定条目上限，实际可编码大小由原生方言帧与控制消息预算决定。

固定原生端点前，短暂的 DNS 和连接失败最多尝试三次，共用每条入口的同一时限，连接仍有
独立的探测超时。重试成功则保留真实端点；用尽尝试仍失败才固定为仅状态入口。用户取消会
直接传播，不转成不可用状态。诊断只包含选服项编号、尝试次数和固定结果分类，不记录地址
或不可信的传输异常详情。本次启动已经发布的原生绑定仍保持不变。

侧边栏和商店共享会话目录与完整插件库存。后台更新检查跨启用来源按游戏及插件身份去重；搜索与来源筛选只影响商店结果。只有一个传输项时，进度放在信息卡片外；多个传输项时，各自进度保留在对应卡片内。

[English](architecture.md)

经审核的游戏模块可通过 `IAutomaticServerSelectionCapability` 声明原生自动选服能力。
服务端要求 gateway 模式并开启 Automatic 时，对应版本在启动 Gateway 和构建资源之前，
先取得绑定本次登录的服务器授权。共享层固定
原始手动入口、已解析的物理端点、认证来源和自动候选范围。健康状态刷新沿用原账号、票据
和授权，不能替换端点或延长授权。服务端报告在线且有时限的 TCP 测量成功后即可参与
自动选择，不比较心跳时间戳。离线节点保留在授权范围中，等待服务端报告在线并测量成功。
完整空快照撤回自动候选，但不会改变原始手动入口范围。

Center 默认关闭。`/v1/catalog` 必须显式提供
`center: { "enabled": true, "mode": "gateway" }` 才会开启本地 Gateway。
显式开启 Center 后，省略 `mode` 默认使用 gateway；只有明确指定 native 才由服务端自己实现。
没有 `center`、没有 `enabled` 或将其设为 false 都保持普通启动流程，
不会请求 `/v1/servers/<build>`。开启后，native 保持原服务端 Center 地址，由服务端自己完成
原生选服和路由，不启动本地 Gateway，也不请求本地自动选服授权。只有开启且模式为 gateway
时才读取目录并准备本地协议组件，目录必须重复相同的开启声明。明确导入且不使用 API 的服务器
也必须在目录中配置 `enabled = true`。在线目录策略优先于本地保存的服务器资料；
客户端构建不提供部署模式开关。

gateway 模式下，服务端通过 `automatic: true` 的入口开启 Automatic，该入口的 `targets`
限定允许的自动候选池。认证启动授权固定实际成员、认证来源、数据范围和端点。仅供手动选择
的节点不会进入自动候选池，健康刷新也不能扩大范围。没有 Automatic 入口时只展示手动目标。
仅支持引导的适配器不能自行预选 Automatic 别名来代替认证授权。模块内置的 Gateway 能力描述
只记录实现能力，不替服务端启用功能或扩大授权。能力描述应随审核后的 Gateway 产物和目标
服务端检查一起更新；配置不等于实机验收。

Gateway Center 登录统一使用游戏原生选服界面和原生跳转协议。自动选择、健康测量与端点路由
由启动器、Gateway 和服务端处理，不使用选服渲染、点击或自动选择 Hook。每个客户端构建
必须核实自己的协议消费路径后才能启用对应能力。CN2012 只保留原生登录流程所必需、
且已核实的认证续接修复。

原生认证组件从会话中读取准备完成的游戏连接地址；有启动引导时，该地址就是 Center 入口。
认证来源和票据仍属于原始认证服务，组件不能在重定向连接时将地址重新覆盖为原来的物理游戏服务器。

启动租约持有一个刷新循环和 READY 之后唯一的控制管道读取者，
校验父进程递增序号，并串行写入刷新和 STOP。授权的绝对截止时间覆盖资源准备和原生跳转。
选定节点后停止刷新，等待 Gateway 完成自己的握手。只有原生跳转和源连接释放握手完成后，
Gateway 才结束引导连接；选定的游戏连接继续独立运行。必要的认证和启动适配与 Center
选服能力分别管理。

原生 BootstrapComplete 状态只开始观察成功移交，不会直接释放启动租约或取消刷新任务。
Gateway 保持控制管道，在自身协议限定的时间内结束辅助连接后自然退出。
游戏退出会取消移交观察，并通过原来的 STOP 路径释放租约；未实现移交观察的提供方
继续持有租约，直到游戏退出。

目录成员范围与节点当前可用状态分开保存。原生自动选服授权保留原始手动映射，并提供真正的
本地自动 Center；普通目录连接独立物理目标。此前的 CN2012 选服展示适配器已移除。
通用 `LaunchBootstrapMetadata` 契约仍可供其他模块能力使用，共享启动流程将其原样写入
`[module_data]`，具体含义由游戏模块校验。详见[原生元数据契约](hook/native-abi.md#launch-module-metadata)。

FantasyTale.Launcher 是面向经典网游社区服务器的多游戏启动器。它负责安装和更新游戏客户端，
让任意多份互相独立的客户端并存，把它们连接到用户选择的服务器，并把客户端 hook 插件加载进
游戏进程。泡泡战士是第一个、目前也是唯一启用的游戏。

启动校验只读取文件。校验通过后，共享启动器在持有客户端操作锁时调用游戏模块可选的
`PrepareLaunch`，然后才部署运行时文件并启动进程。游戏特有的持久设置同步放在这个阶段。
泡泡战士会将已有 `login.ini` 同步到所选服务器；设置相同时不重写文件。

核心原则与配套的服务端项目一致：**凡是会变化的东西都是数据或插件，而不是改代码。**

启动时只显示居中的静态 Logo，不显示文字或进度环。工作区绘制后平滑交叉淡入，
不设置最短展示时间。标题栏挂载在固定工作区的层叠上下文之外，加载画面也能使用
最小化、最大化／还原、关闭和拖动。启动过渡完成前关闭会退出启动器；
过渡完成后，手动点击右上角关闭会询问结束启动器、退出到后台或取消；原生关闭请求仍隐藏到托盘。
前端在动画结束后显式通知宿主就绪。加载背景固定为纯白色，Logo 入场保持不变。Logo 入场完成后，加载层先淡出并移除，
工作区再通过 Web Animations 播放完整入场，避免动画被遮挡。取消按钮和 Esc 只关闭弹窗，不退出或隐藏窗口。
关闭选项会先播放完弹窗离场动画，再隐藏或退出启动器；减少动画模式保留简短淡入淡出，不使用空间位移。精简透明 PNG 和多尺寸 ICO 分别用于启动画面、
程序、窗口和按 DPI 缩放的托盘图标。
游戏、客户端版本、服务器、下载源、插件商店和 hook 插件都由 TOML 文件描述，在运行时发现。

前端保存仅用于显示的游戏定义、客户端名称、已安装标记和语言信息，并为每个游戏记住上次选择的客户端与版本。
后台读取本地记录前先恢复这些信息；缓存里的真实版本可以立即选择，已安装客户端可以直接点击启动，
无需等待后台游戏列表或客户端列表返回，避免将加载过程误显示成客户端缺失或虚构的“默认版本”。
没有缓存时，主页显示加载状态，直到已保存的客户端列表读取成功。读取失败保留缓存；
读取成功则以实际列表替换，包括确实为空的情况。进程状态查询独立更新。
实际启动时后端读取对应的客户端记录，缓存字段不会覆盖设置；更改客户端语言及编辑、复制记录
仍使用首次成功读取的完整信息。
缓存不包含安装路径、插件选项或账号会话凭据；实际启动仍以后端校验为准。

```text
+--------------------------------------------------------------+
```

* `web/` 是独立的 Vite 项目，产物复制到宿主的 `wwwroot`。Windows 在本地拦截
  `https://fantasytale.invalid/`，其他平台保留 `app://localhost`。仅此精确来源可以读取
  指定根目录下白名单允许的静态文件与媒体，本地缺失路径不会转为网络请求。
  文件系统和服务操作通过桥接进行。目前宿主会缓冲整个媒体响应，尚不支持视频范围流式读取。
* `Host` 负责窗口和桥接，不包含任何游戏逻辑。
* `Core` 和 `Downloads` 与具体游戏无关。
* `Sdk` 是游戏模块唯一引用的程序集，按 SemVer 版本化，是闭源模块依赖的稳定接口。

## 2. 开源与闭源的划分

启动器本体和所有泡泡战士相关内容开源（MIT）。TalesRunner 和 AirRider 的支持在**独立的私有仓库**
中开发，只引用公开的 `FantasyTale.Launcher.Sdk` 包和公开的原生 hook ABI：

* 公开仓库包含展示用的 `games/<Game>/game.toml`，标记 `status = "placeholder"`，以及共享账号组件使用的等级表和图标。配置
  `home_order` 后可以在主页轮播中浏览，但不会启用游戏模块。`preparing` 独立控制页面的准备中提示：
  跑跑飞空艇使用正常的游戏库页面，超级跑跑显示准备中。实际启动仍然需要启用的模块和受支持的客户端版本。
* 私有模块构建成"游戏模块包"（包含 `game.toml`、托管程序集，以及需要的原生 hook 插件）。
  放进用户的 `games/` 目录即可使用；公开启动器对它没有任何编译期依赖。
* TalesRunner 的专用 patch SDK 和 AirRider 的 hook 都放在各自的私有仓库，使用与泡泡战士相同的运行时 ABI。

托管模块按安装程序集路径使用独立的加载上下文。模块包应包含它的私有 DLL、
`.deps.json` 及适用的运行时专用依赖。解析器优先使用该清单，也支持手动组包时
放在模块旁边的托管 DLL。每个上下文共享宿主的 `FantasyTale.Launcher.Sdk` 程序集，
因此即使包内附带一份 SDK，启动计划和可选 SDK 接口也保留相同的类型身份。
框架依赖沿用 .NET 的正常解析流程。加载上下文在启动器进程内复用；替换已加载的
模块或依赖后，需要重启启动器。这提供依赖隔离，不是安全沙箱。游戏目录中已安装
的模块优先；只有该文件不存在时才回退到应用目录。游戏目录中的模块损坏或依赖
缺失时会报告错误，不会改用内置模块。

托管模块调用的原生依赖运行在 Launcher 内，必须匹配 Launcher 进程的架构。它们与
加载到游戏内的 Hook DLL 不同，后者必须匹配游戏进程的架构。Windows 模块包测试
实际验证了两个目录下同名原生库的程序集作用域加载，包含有、无组件清单的情况，
并验证缺少原生库会报错。这些合成模块检查不代表两款私有游戏已经通过实际验收。

## 3. 用定义代替代码

客户端版本在 `[build]` 中提供可恢复的可用性开关：`enabled` 默认 `true`，`hidden` 默认
`false`。停用或隐藏的版本不会出现在版本选择、服务器预设和客户端下载入口中。
`enabled = false` 还会在开始实际操作前阻止新建客户端、安装、游戏启动和本机托管，
但保留识别特征、插件兼容定义，以及现有客户端文件和设置。单独设置 `hidden = true`
只改变入口展示，不改变启动条件。适配完成后设置 `enabled = true`、`hidden = false`
并重新打开启动器即可恢复。目前已声明的国服 2016 版本 `cn-735` 暂时停用并隐藏；
台服 2019 仍按其版本定义保留，不会因为可执行文件签名日期为 2018 年而一并停用。

| 文件 | 描述内容 |
| --- | --- |
| `games/<game>/game.toml` | 游戏 id、多语言名称、美术资源、模块程序集、hook 宿主类型 |
| `games/<game>/builds/<build>.toml` | 一个客户端版本：id、分支、地区、可执行文件名、识别特征、信使模式、默认插件 |
| `games/<game>/plugins/<id>/plugin.toml` | 一个 hook 插件（见 [hook/plugin-format.zh.md](hook/plugin-format.zh.md)） |
| 用户的 `servers.toml` | 用户添加的服务器（服务器启动器 API 的地址） |
| 用户的 `sources.toml` | 下载源和插件商店源 |
| `<实例>/instance.toml` | 一份已安装的客户端：版本、绑定的服务器、启用的插件、选项 |
| `<实例>/session.toml` | 每次启动时由启动器写入、由 hook 运行时读取（见 [hook/session-contract.md](hook/session-contract.md)） |

新增客户端版本、服务器或 hook 都只需写一个文件。只有出现新"种类"的行为时才需要改代码。

主页展示同样由 `game.toml` 提供：

`game.navigation_entries` 声明支持的菜单路由标识，可选值为 `home`、`instances`、
`multiplayer`、`hosting`、`store`、`downloads`、`plugins`、`accounts` 和 `settings`。
标识不能重复且必须包含 `home`，未知标识会使配置加载报错。旧声明未提供此字段时，
仅开放 `home`、`downloads`、`accounts`。桥接将校验后的列表传给侧边栏与路由检查，
浏览器预览也读取同一组 TOML 声明。配置加载完成后，切换游戏或访问不支持的旧路由
会返回主页。主页快捷入口也读取同一份声明。服务器对插件的限制作用于相应操作，
不会隐藏已经由游戏声明开放的插件库入口。

* `game.home_order` 是可选的 0 到 10000 整数。已启用的游戏和配置了该值的游戏按数值升序排列，
  同值时按游戏 id 排序。到达列表首尾时，分别隐藏上一个、下一个游戏的箭头。
* `game.unsupported_regions` 是可选的、不重复的启动器界面语言标签列表，例如 `["zh-CN"]`。
  仅在界面语言与其中某项完全匹配时隐藏主页游戏入口，匹配忽略大小写；省略或空列表在所有语言显示。
  切换其他界面语言会立即恢复符合条件的入口，已安装客户端和保存数据不会被删除。
  当前游戏被隐藏时，在启动器空闲后选择第一个可见游戏。此配置与所选游戏语言、IP 所在地无关，
  也不用于访问权限控制。目前内置配置均未启用。
* `game.preparing` 对占位模块默认为 true，对已启用模块默认为 false。`game.service_notice`
  是显示在封面下方的可选多语言提示。小标题固定为游戏英文名，大标题使用界面语言；与英文名相同时改用韩文原名。
* 内置服务器独立保存在 `games/<game>/servers/*.toml`，不写入 `game.toml`。
  泡泡战士内置配置为 `FantasyTale.toml`，其中 `server.id = "FantasyTale"`；
  本地覆盖使用相同身份。内置 profile 可用 `icon_asset` 指定网页资源内的图标，
  外部导入的 profile 不能自行声明这种内置资源权限。
* `game.media.background_videos` 是有序列表，最多 16 项，使用相对于游戏目录的本地 MP4/WebM 路径。
  空列表显示配色背景。旧的 `background_video` 键支持单个路径，不能与列表同时配置。路径不能超出游戏目录，
  大型媒体文件不进入 Git。
* 每个封面默认静音，提供声音开关。多段视频额外显示切换按钮和序号，自动顺序播放并循环。
  切换视频保留声音选择，切换游戏恢复静音。视频首帧就绪后淡入；离开页面停止播放，页面隐藏时暂停。
  播放失败的视频会被跳过，全部失败时显示提示和背景。

## 4. 实例

**实例**是一份独立的客户端，拥有自己的目录、绑定的服务器、插件组合和选项，类似 Minecraft
启动器里的版本隔离。实例数量不限，同一版本也可以装多份，因为不同服务器可能需要不同的文件或 hook。

“添加客户端”选择的是安装目标目录。可选的绝对路径字段 `instance.installation_path` 指向该目录；
未指定时使用管理目录下的 `client` 子目录。检测到已有客户端时直接登记，不询问覆盖；
重复登记相同版本和目录时复用已有记录。其他非空目标目录仍会在创建前询问是否允许覆盖。
登记客户端本身保留现有文件；实际安装包覆盖由经过校验的清单安装器执行。客户端目录之间以及客户端目录与
启动器管理目录之间不允许重叠。移除使用外部安装路径的客户端时只移除启动器配置；复制客户端则复制文件，
创建独立的受管理目录。此弹窗的语言选择保留为注释代码，主页仍可选择游戏语言。

添加客户端时名称可以留空，前端会使用所选版本的本地化展示名。创建时在登记锁内
分配首个可用名称，重名依次使用“名称 (1)”“名称 (2)”并写入配置。
内部 ID 与安装路径不受展示名称影响。

后续阶段会加入实例共享的内容寻址存储（文件系统支持时使用硬链接），让重复的客户端文件只存一份。
无论是否启用该存储，实例目录结构都不变。

## 5. 服务器与启动器 API

通过服务器的启动器 API 地址添加服务器。该 API 是服务端的可选插件（对泡泡战士而言，是
BubbleFighter.Fantasy 中的一个插件行），提供：

* 服务器信息：名称、在线人数、支持的版本、公告；
* 账号注册与登录（密码由服务器校验）；
* 账号概要：名称、金币、经验；
* 每个版本的客户端分发清单：文件列表（大小和哈希）、每个文件的获取位置、必选和推荐的 hook 插件；
* 短期有效的**登录票据**：启动器通过 `session.toml` 交给客户端，信使替身把它作为 passport 返回，
  客户端在登录请求中发送它，游戏服务器据此校验。

没有该 API 的服务器仍可按地址手动添加，此时行为与现有启动器相同（无密码校验、无自动安装）。

## 6. 下载

游戏模块可以通过可选的 `ILocalServerModule` SDK 能力交给启动器管理本机服务端包。
共用调度代码负责进程归属、正常退出、有上限的诊断记录和临时账号连接；游戏模块生成
独立配置补丁，不修改原服务端包。当前适配器和待完成的联机部分见[本机托管](local-hosting.zh.md)。

* 内置 HTTP 引擎已实现断点续传与流式哈希校验；通过 JSON-RPC 接入 aria2 仍属后续计划。
* 下载源：普通 HTTP(S) 和 **AList**（`/api/fs/get` 获取签名的 `raw_url`，`/api/fs/list` 列目录，
  token 可选）。支持 AList 但不强制：清单条目给出下载源 id 和路径，任何能把路径解析成 URL 的下载源类型都可用。
* 每个文件在移入目标位置前都按大小和哈希校验。安装器通过持久化回滚记录执行清单中的新增和替换；
  删除、移动和重命名操作仍待实现。

当前前端提供可手动开启的客户端与启动器更新开发预览。总字节进度和当前文件进度分别显示，
仅在传输期间显示速度与预计剩余时间。暂停、校验、安装、失败和完成状态共用同一任务模型。
预览数据仅保存在内存中，不会下载、安装文件或重启程序。真实客户端任务通过独立的宿主状态复用这些界面；
启动器更新现已复用这些界面，由独立进程替换文件，等待前端就绪后提交，失败时回滚。
具体流程见[启动器自身更新](launcher-updates.zh.md)。

主页卡片在桌面工作区内保持固定高度。展开更新详情时压缩视频区域，让客户端操作以及服务器、
账号、游戏语言栏始终可见。状态行明确提供“展开详情／收起详情”，独立的“打开下载页面”按钮
用于进入对应任务。下载页面的任务列表和文件明细各自在容器内滚动，标题、进度和任务控制保持可见。
任务数量只显示在分类标签中，全部任务的总下载速度放在分类栏右侧；所选任务的进度详情仍显示该任务的下载速度。
“文件”和“下载来源”标签位于同一个默认收起的详情区域内。展开和收起时，高度及透明度在工作区剩余空间内
平滑过渡，箭头同步旋转。内容在内部滚动，标签保持可见。切换任务后收起详情；收起时，上方单文件进度恢复
跟随当前文件。系统开启减少动态效果时禁用这些动画。

商店来源管理以及 AList/HTTP 共用的目录格式见[商店来源](store-sources.zh.md)。
客户端文件清单、下载和事务安装已经接通；商店插件下载与可信启动器更新仍是后续独立阶段。

## 7. Hook 插件（客户端）

国服 2013（`cn-406`，原始版本 `0.2.35.001`）通过
`launch.login = "gamewidget-ticket"` 与 `launch.login_module = "sdologinentry.dll"`
选择登录桥接。游戏模块把已校验的桥接 DLL 纳入同一套运行时部署与恢复事务。
桥接入口转发到现有信使宿主，共用一份会话、就绪检查和通信通道。只有必需插件成功后，
它才交付账号及带完整标记的一次性服务器票据；不从账号文件或环境变量回退读取身份。
其他版本保留各自的登录方式。原生接口依据见[登录桥接契约](hook/cn-login-bridge.md)。

客户端退出后，原生部署还原会在整次还原共用的两秒重试窗口内，重试 Windows 的访问拒绝、
共享冲突与文件锁冲突。每次尝试都会重新校验目标及原始备份摘要，再执行替换。其他错误或
外部字节修改会立即拒绝。持续占用时明确报错并保留事务日志和原始备份，供确认客户端停止后
恢复；不能仅凭进程退出就认定所有 DLL 读取者都已经释放文件。

桌面启动通过异步工作线程执行模块准备与系统启动调用。待启动请求占用有数量上限的
名额，并持有客户端锁，但不持有运行状态锁，因此系统确认等待不会阻塞运行中客户端
查询。重复启动会被拒绝。明确退出或关闭启动器时，先等待待启动请求完成，再停止或
等待已返回的进程；待启动请求也纳入更新与退出的活动客户端判断。启动器不取消或绕过
Windows 权限提示；取消提示后按启动失败路径还原文件并清理会话。

启动中断后，客户端页会显示“恢复客户端”。恢复要求明确确认游戏已关闭，并取得客户端锁；
发现同路径游戏进程仍运行，或无法检查进程时，会拒绝操作。遗留会话必须与客户端、游戏和
版本一致，之后才可还原。验证或哈希还原失败时保留原始 DLL 备份和会话；成功后删除会话，
诊断日志保留。不允许克隆或导入尚未恢复的原生部署；只有会话而没有部署时，复制客户端仍
排除会话文件。恢复不会结束未监控的游戏，并要求在明确确认的维护操作期间，没有外部程序
重新启动该游戏。

hook 运行在游戏进程内，以插件形式交付：

* **FtHook 运行时**（`native/runtime`）：x86 静态库。它识别客户端版本，等待加壳的可执行文件在内存中
  解壳完成，然后加载 `session.toml` 列出的插件，校验兼容性并应用，每个插件写一行结果。
* **每个游戏一个宿主**。泡泡战士的宿主是 `nmcogame.dll`，所有客户端版本都会导入它。同一个二进制
  导出所有版本出现过的信使入口的并集，并以两种模式之一运行：
  * `standin`：自己应答信使协议（不依赖 Nexon 服务）；
  * `forward`：把每个调用转发给改名为 `nmcogame.nexon.dll` 的原版库。
  由于客户端在解壳器运行之后才加载它，补丁可以避开 `version.dll` 代理会撞上的防篡改窗口。
* **声明式插件**用数据描述补丁：如何定位（特征码、按版本的固定 RVA，或命名定位器）、该处应有的原字节、
  要写入的字节。新增插件不需要重新编译。
* **原生插件**附带一个使用简单 C ABI 的 DLL，用于需要代码的 hook（detour、观察器），可以使用运行时的
  定位、补丁和日志服务。
* 每个插件声明 SemVer 版本号、支持和禁用的版本、在哪些版本上必选，以及带类型的选项（启动器据此生成设置表单）。

“插件”页通过当前用户的独立插件库导入本地文件夹和 ZIP。暂存预览经过校验后才正式
安装，导入不执行代码，也不改变任何客户端的选择。每个客户端固定使用自己选定的
插件版本，本地导入不能占用内置标识或声明全局强制要求。限制与启用行为见
[插件管理](plugin-management.zh.md)。

## 8. 前端

游戏运行时启动器保持打开。关闭窗口会隐藏到托盘；明确退出时会确认是否结束正在运行的游戏。
按用户及数据目录隔离的互斥锁与激活事件让重复启动唤回首个窗口。
就绪状态和停止操作使用[本地 Hook 协议](hook/control-protocol.md)，
可选的崩溃和接收记录见[诊断指南](diagnostics.zh.md)。

主页卡片及版本选择栏在切换游戏时保持尺寸，只有一个版本的游戏也保留版本栏。
标签内容共用短暂的淡入及位移动画，遵循减少动画偏好；侧边导航按钮不会显示浏览器链接状态文字。

Vue 3 + Vite + TypeScript，使用 Launcher 自己维护的控件层。目标是让窗口与原生 WinUI 3 应用无法区分：
自绘标题栏、宿主提供的 Mica 背景、NavigationView、Fluent 动效，没有浏览器右键菜单、文字选择和滚动条痕迹，
并在 WebView 加载期间显示原生风格的启动画面。界面支持七种语言：zh-CN、zh-TW、ko、id、vi、th、en，默认跟随系统语言。
文案按语言保存在 JSON 中。泰语客户端日期标签使用泰国佛历，保存的日期、版本标识和用户输入名称保持原值。
尚未翻译的泰语文案保留英文。

繁体中文（`zh-TW`）的客户端地区统一写作“中國、韓國、台灣、印度尼西亞”，
项目插件／模组称为“模組”，二进制或程序模块称为“程式模組”。游戏正式名称使用“泡泡大亂鬥”，
服务器名 `Bubble Fighter Fantasy` 不翻译。简体中文继续使用“国服、韩服、台服、印尼服”和“插件”。
语言字典、游戏／版本／插件展示定义及浏览器预览数据均遵循对应语言规范；不翻译或重命名内部标识、TOML 键、API 字段或协议术语。

窗口默认以 1360 x 840 逻辑像素打开，并根据当前显示器的工作区限制尺寸。标题文字和窗口按钮
位于顶部 32 像素区域，导航区从 48 像素高的标题区域下方开始。侧栏默认收起为 56 像素宽的图标栏，
展开后宽 256 像素，并记住用户主动展开的选择；在较窄的窗口中，侧栏覆盖在内容上方，选择页面后自动收起。
设置固定在底部，导航列表独立滚动。卡片保留一像素细边框，在明暗主题中都提供适度的边界对比。
设置卡片撑满可用内容宽度，并保留统一的页面内边距。

WebView 背景可以透明以显示系统背景材质，但原生窗口必须保留正常的矩形点击区域，不能使用
会让透明像素把点击传给下方应用的分层窗口。最大化遵循显示器工作区，还原操作读取原生窗口状态。

## 服务器接线与设置

启动器先请求公开 `/v1/catalog` 基本信息。HTTP 域名入口失败时，使用实时 DNS 解析地址重试基本信息请求，不携带凭据。启动器不固定部署 IP 或地区。系统 DNS 返回代理生成的 198.18.0.0/15 地址时，改用 HTTPS 公共 DNS 查询；密码和令牌不会发给 DNS 服务。

后续请求依次采用服务器显式 `hostPolicy`、单台服务器可为空的本地 `prefer_ip`、全局 `ip_preference = "china" | "all" | "disabled"`。默认为仅中国地区，以服务端地区为准；未下发地区时，CN 注册地址段只是尽力判断，不能保证实际机房位置。HTTP 直接采用 IP 地址和 Host；HTTPS 保留域名和正常证书校验，不通过 HTTP 的 Host 处理绕过 TLS 身份检查。

服务器以数据目录下 `servers/<id>.toml` 独立保存。实例 TOML 保存版本、语言与插件；选择服务器不会覆盖实例连接配置。服务器明确下发的字段（包括 false 和空列表）覆盖本地能力、登录及语言选项。未知版本可以显示为预设，但没有本地模块时不能安装或启动。

登录/注册共用对话框，动态注册字段是有界服务端数据，只作为文本和表单控件呈现。令牌不传给前端；访问令牌只保存在内存，刷新凭据使用当前 Windows 用户的受保护存储。未知账号数值显示短横线；泡泡战士和跑跑飞空艇显示等级/LUCCI/Cash，超级跑跑显示等级/EXP/TR/Cash。服务器可提供 HTTPS 等级图标，失败时回退数字。

可选 `game.media.background_audio_tracks` 与视频列表逐项对应，空字符串使用视频原音轨。独立音轨跟随视频时间、暂停、静音和播放列表切换；音轨失败时保留视频并显示提示。游戏语言与启动器界面语言独立，计划中的版本语言可以提前选择并保存，模块功能仍需后续完成。

等级、经验和本地图标通过 `game.levels` 指向的 TOML 与源表配置，详见 [等级数据](levels.zh.md)。特殊图标只覆盖外观，保留正常等级和经验。

## 服务器账号选择

每个本地服务器标识和 API 地址独立保存账号会话，不设固定的账号或服务器数量上限。
公开 Bridge 一次返回当前账号和账号列表，不传递访问令牌。登录只新增或替换对应账号，
不覆盖其他账号。密码和访问令牌不落盘。刷新凭据和上次验证的资料使用当前 Windows 用户的
DPAPI 加密后原子保存到数据目录。重启后，所选会话会在请求账号信息或启动票据前取得新的
访问令牌。访问令牌过期或意外 HTTP 401 会触发串行刷新；临时网络失败保留刷新会话。
服务端也必须跨重启保留刷新会话哈希。详见[认证合同](launcher-auth.zh.md)。

首页账号下拉可切换会话，末项为“添加账号”。账号页按服务器分组展示所有已登录账号，
支持切换、刷新当前账号资料和单独退出登录。退出账号不会自动选中另一个身份。
登录失败不清除已有账号；远端拒绝只使该请求使用的令牌失效。修改服务器会阻止旧登录
请求恢复会话。申请启动票据期间若切换了账号，即使又切回原账号，也会拒绝旧票据。

登录成功响应较慢时，新账号可以加入列表，但不会夺回等待期间已经改变的当前选择。
同名账号会话若在此期间被重新登录、移除或过期，旧响应不能替换它；用户需要按当前状态重试登录。


### 功能暂时停用

`game.rooms_enabled` 与 `game.local_hosting_enabled` 是经过校验的布尔值，
旧定义默认均为 `true`。设为 `false` 时保留实现与已有配置。本机托管导航入口
显示为禁用，直接访问该页面会显示开发提示且不轮询。房间浏览、加入和发布
暂不可用，服务器标签、已保存服务器、发现、提交和连接服务器继续可用。
后台以 `feature_in_development` 拒绝禁用操作；停止已有进程和撤回发布仍可用于清理。
后续验收通过后，在游戏声明中分别启用即可。

国服认证组件负责原生连接票据适配。游戏模块可通过既有不透明模块元数据通道，按原生服务器 ID 提供 CN2011 的可选 Center 标题。缺失名称时保留原生固定标题，Gateway 封包和路由不变。可选标题调用点适配与票据赋值独立，不能称为零 Hook。
