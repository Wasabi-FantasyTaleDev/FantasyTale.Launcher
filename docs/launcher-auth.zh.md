# 启动器账号会话

启动器默认不保存密码，访问令牌始终不会持久化。刷新凭据使用当前 Windows 用户的
DPAPI 加密后保存到启动器数据目录。这个受保护文件不会暴露给前端、游戏实例、
插件或启动器更新包。启动器启动时会恢复上次验证过的账号资料，并在读取账号
信息或请求启动票据前静默换取新的访问令牌。

只要受保护的刷新会话仍有效，未选中的账号就会保留在列表中，重启 Launcher 后也一样。
返回前端的公开账号快照包含访问到期时间 `expiresAt` 和可选的刷新到期时间
`refreshExpiresAt`，不包含访问令牌或刷新凭据。界面仅在两种可用期限都已到期时
移除账号；选择保留的账号后，会在认证请求前续期。服务器拒绝会话时，仍只移除对应账号。
自动续期拒绝当前会话后，账号列表会返回其他保留账号，且不自动选择其他账号。
服务不可用、目录请求被拒绝、响应格式错误和需要升级启动器仍会返回对应错误，
不会因此丢弃保留的会话。

首次读取账号会话和服务器登录信息时，主页的账号区域显示转圈，主按钮保持蓝色并显示
“正在连接”。版本选择仍可正常操作；请求结果确认前不会重复打开登录窗口。
恢复成功后直接显示角色信息；会话为空或被拒绝时恢复正常登录，失败后结束加载并保留错误提示。
其他服务器迟到的响应不会结束当前服务器的加载状态或替换账号。同一服务器后台刷新时，
已有的有效角色信息会保留，不会短暂显示成“未登录”。手动提交登录后，按钮也会显示加载状态，
直到请求结束。这些动画不保存凭据，也不会自动提交记住的密码。

## 记住密码

登录窗口提供默认不勾选的“记住密码”。只有勾选且登录成功后才保存密码，使用独立的
Windows 用户加密文件 `remembered-logins.bin`。重新打开同一服务器的登录窗口时，自动
填入最近一次记住的账号和密码，并保持勾选；不会自动提交登录。修改账号名时会清除
尚未手动修改的自动填入密码。切换服务器、注册、关闭窗口或离开页面都会清除表单秘密，
并拒绝迟到的自动填入结果。密码按服务器 ID 与确切的 API 地址隔离，不绑定客户端版本。

退出登录会撤销刷新会话，但保留用户明确选择记住的密码。取消勾选后成功登录，会清除
该账号保存的密码。登录失败不会保存新密码或清除之前的选择。编辑或移除服务器会忘记
它的密码。密码和刷新会话存储不设固定的账号数量或文件大小上限。
损坏或无法解密的文件不能自动填入。密码文件和刷新会话文件都不能进入启动器发行包。

注销与该账号的刷新共用互斥门：已经进行的刷新完成后，注销使用轮换后的新凭据撤销
会话。等待期间切换账号不会改变注销目标，同名账号重新登录也不会被旧操作移除。
取消等待会保留账号。移除之后发生远端失败时仍会报告错误，其他账号保持不变。

## API 合同

启动请求的 `build` 始终表示 wire version，例如选中的客户端 Profile 为
`kr-1256-2` 时，仍发送 `kr-1256`。同一个 `POST /v1/launch` 请求可附带
`release_version` 和 `patch_version` 字符串；未知时省略。服务端按 `build`
选择协议，另外两个字段仅描述客户端，不参与协议选择。通过客户端定义启动时，同一次
请求也会传入数值型 `protocol_version`。启动绑定点击时的账号；续期或申请票据期间切换
账号会取消这次启动，即使切换后又选回原账号也一样。

启动时，宿主复用已验证的服务器目录信息；主动刷新仍会读取服务器。缓存按服务器 ID、
确切的 API 地址和游戏隔离。编辑或移除服务器会使缓存失效；迟到的响应不能恢复已移除
的作用域，也不能覆盖后完成的新目录。没有已验证的缓存时，宿主先读取公开目录。
已加入的房间仍需检查源中的成员关系。这些检查、凭据续期和必需插件下载，可能使首次
启动或配置改变后的启动产生额外请求。

泡泡战士会读取可选的 `version.dat`：`[PATCH] VERSION` 提供 patch version，
`[Common] Version` 提供 release version；没有 PATCH 时，Common 的值也用作
patch version。文件缺失、无法读取、过大或字段无法识别时，回退到 Profile 中
可选的 `release_version` 和 `patch_version`。此文件不是启动必需品，也不会增加网络请求。

同一个启动请求还携带 `launcher_language`（启动器当前界面语言）、`native_language`
（原始客户端语言）和 `client_language`（本次使用语言，可由已安装语言包提供）。
未知的客户端语言信息省略，不用于选择协议。选择翻译不会改变原生语言，且不会为语言
信息额外发请求。恢复会话、刷新令牌或一次认证重试仍可能按需增加请求；已有新鲜有效
会话时只发送一次启动票据请求。

`POST /v1/auth/login` 接收 `{ "username", "password", "launcherVersion" }`，返回账号资料时
必须包含下面的会话字段：

```json
{
  "accessToken": "opaque-access-token",
  "accessExpiresAt": "2026-10-10T18:30:00Z",
  "refreshToken": "opaque-refresh-token",
  "refreshExpiresAt": "2026-11-09T18:00:00Z",
  "account": { "username": "player", "displayName": "player", "stats": {} }
}
```

访问令牌应当短时有效，刷新令牌应当长期有效。服务端只保存刷新令牌的哈希，
并将它限定到对应账号和启动器客户端。每次刷新成功后都应轮换刷新令牌并撤销
旧值。两个令牌都不能写入日志或错误响应。

`POST /v1/auth/refresh` 接收 `{ "refreshToken": "...", "launcherVersion": "0.1.14" }`，并用同样的四个字段
返回新的访问令牌和刷新令牌。启动器会在访问令牌临近过期时自动刷新；同一账号
的并发刷新会合并；如果仍有效的访问令牌被服务端拒绝，启动器会刷新一次并重试。
刷新令牌失效或过期时，只移除该服务器上的该账号会话，然后要求用户重新登录。

`POST /v1/auth/logout` 接收 `{ "refreshToken": "..." }`，访问令牌可用时也发送
Bearer 请求头。服务端必须允许仅凭刷新凭据登出，以支持启动器重启后尚未刷新时立即
移除账号。该请求只撤销对应的刷新会话及未使用票据，成功时返回 HTTP 200 和 JSON 对象。因此，
启动器重启后不需要重新登录；只要服务端仍保留有效的持久刷新会话，服务端重启
后也不需要重新登录。如果访问令牌被拒绝，启动器会静默刷新并将原请求重试一次。

临时网络失败和 HTTP 5xx 不会清除已保存的刷新会话。启动器重启后，会在发送恢复的刷新
凭据或注销请求前重新获取服务器访问策略。公开配置发现可以不带凭据，将普通 HTTP
请求改为解析后的 IP 重试；随后经过校验的服务器策略覆盖本地 IP 偏好，控制认证请求。
配置接口拒绝请求不代表刷新令牌被拒绝，因此不会删除刷新凭据。用户主动注销时，
即使配置发现或服务端撤销失败，仍会移除本地账号，并向用户报告失败。
API 期限使用注入的时钟校验：
访问令牌有效期必须在 24 小时以内；刷新令牌期限必须晚于访问令牌，并在 365 天以内。

只有在刷新令牌过期或被撤销、服务端拒绝账号、用户主动退出登录，或者受保护的
Windows 用户存储无法打开时，才需要重新登录。例如更换 Windows 用户或删除启动器
数据都可能导致这种情况。

## 启动器版本与插件策略

所有启动器 API 请求都携带 `X-FantasyTale-Launcher-Version` 请求头。登录、注册、
刷新和启动请求的 JSON 还携带 `launcherVersion`。其值使用打包时的应用 SemVer，
去除源码元数据，与“关于”页面和兼容性判断一致。按数字分段和预发布优先级比较：
`1.0.10` 高于 `1.0.9`，`1.0.10-rc.1` 低于 `1.0.10`，不另维护数字版本计数。

公开 catalog 与成功登录／刷新响应可以增加以下可选字段：

```json
{
  "minimumLauncherVersion": "0.1.33",
  "clientPolicy": {
    "version": 1,
    "sources": [{ "name": "community", "kind": "http", "baseUrl": "https://plugins.example/", "catalogPath": "source.toml" }],
    "plugins": [
      { "id": "bubblefighter.fantasy.font-weight", "rules": [{ "id": "offer", "type": "recommend", "builds": ["kr-812"], "sources": ["community"] }] },
      { "id": "bubblefighter.fantasy.cn-auth", "rules": [{ "id": "need", "type": "require", "builds": ["cn-404"] }, { "id": "floor", "type": "min_version", "builds": ["cn-404"], "version": "1.0.2" }] }
    ]
  }
}
```

两个字段均为可选。策略格式见[联机指南](multiplayer.zh.md#服务器插件策略)。启动时使用所选账号最近一次登录或刷新
得到的策略；目录中的副本只在登录前显示。插件通过玩家已添加的商店解析，策略不能提供可执行文件路径或下载地址。

版本不足时返回 HTTP 426：
`{"error":"launcher_update_required","minimumLauncherVersion":"0.1.14"}`。
启动器保留账号并引导到共用更新界面。公开 catalog 必须允许旧启动器读取；注销必须
豁免最低版本限制，包括重启后仅凭刷新令牌注销。扩展元数据错误时明确拒绝；刷新响应
中的有效轮换凭据先保存，再检查扩展字段，避免因错误策略或更高版本门槛丢失唯一
有效的刷新令牌。

内置 WebUI 的“认证”选项卡及部署策略配置属于服务端。启动器完成接入不表示服务端
页面或线上部署已经更新，两者须由服务端分别验收。

## 部署要求

启动器客户端会严格校验并使用这个合同。只返回旧的单一
`token`/`expiresAt` 的服务端不满足当前测试合同，会被判定为无效会话响应。
现已使用真实已有账号验证部署的访问/刷新 API：登录与账号资料、独立进程重启后免密码
恢复、轮换与旧令牌拒绝、仅刷新凭据登出，以及按构建签发的原始启动票据。
受控访问 HTTP 401 后真实调用部署的刷新接口并成功重试。这证明客户端恢复行为；
不表示本次重启了已部署服务端，也不表示真实游戏已经加载了角色。
