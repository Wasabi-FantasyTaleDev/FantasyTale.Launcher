# 本机服务端托管

[English](local-hosting.md)

本机托管在玩家电脑上运行独立安装的服务端包，配置与远程服务器、游戏客户端分开保存。
共用适配器由各客户端版本数据声明，支持 cn-279、cn-324、cn-404、cn-406、cn-706、
cn-717、cn-774、id-400、id-1809、kr-812、kr-1256 和 tw-454。已禁用或隐藏的版本仍不开放。
内置版本定义与商店版本配置都包含此声明，已安装客户端记录单独保存。共用进程管理不包含游戏或版本特判。

## 使用界面

“单机游戏”复用兼容的单机配置，或使用默认端口、本地存档和名字登录创建配置；
服务端就绪后启动所选客户端，不再经过配置向导。没有兼容的服务端包时，选择来源并确认安装，
弹窗显示真实下载和安装进度，完成后继续。高级设置默认收起。

打开“本机托管”可以创建或编辑配置。
目录应包含发布后的 `BubbleFighter.Fantasy.Host.exe`、依赖、插件、profiles、packets
和所需的 client-data 资源。已登记的客户端直接提供自己的压缩资源和散文件根目录，
不会复制游戏文件；未指定客户端时使用包内 `client-data/<profile>/data` 和 `dataraw`。
服务端必须支持 `run --managed-stdio`。
旧包会明确启动失败，不会被误认为已经就绪。

“单机游玩”将游戏和账号监听地址限制在 `127.0.0.1`；“创建联机房间”监听全部 IPv4
接口，并公布房主填写的地址；局域网模式绑定所选网卡。管理后台始终只监听本机。
游戏、中继、API 和管理后台四个端口可以分别设置，不能重复；新配置自动取得四个可用端口，
现代客户端同时配置中继监听。
启动器不会自动建立防火墙规则，也不会将私网地址显示为已经可以跨互联网访问；自动组网待后续实现。

可以选择玩家数据的保存方式。新配置默认使用“本地存档”：启用服务端包的 SQLite
提供者，使用稳定的 `hosting/data/<配置标识>/save.sqlite`，正常停服重启后保留账号和进度，
无需另行配置数据库。需要包含 SQLite 插件及其原生依赖的完整服务端包，旧包会明确报错。
“服务端配置的数据库”使用包内及进程环境已配置的数据库；“临时数据”启用有容量限制的
内存存储，进程结束后账号和进度消失。任何模式失败都不会擅自切换到其他模式。
已有配置继续保留原来的程序包数据库或临时模式，直到用户主动修改。

“启动服务端”等待进程实际就绪；随后“前往游戏”在主页选择本机连接。
新的单机和房间配置默认使用名字登录；服务端明确公布此策略，启动器仅对采用该策略的房间连接
传递普通名字。开启账号认证后使用正常注册、登录和启动票据流程。已有配置保留原选择。
名字登录需要运行时 3.6.0；使用韩服认证插件时需 0.1.3，使用国服认证文件桥时需 1.0.2。
“打开管理后台”打开服务端现有
Web 界面，启动器不重复实现玩家、游戏业务和服务端插件的管理功能。

标题、状态和主要按钮固定可见，日志在有大小限制的容器中展开和滚动。
停止服务端会提示玩家将断线，有受管游戏正在运行时会拒绝停止。移除配置保留服务端文件和玩家数据。

## 进程归属与退出

每次启动有独立标识，停止和日志请求必须携带该标识，旧请求不能影响重新启动的进程。
服务端目录内的独占锁阻止多个启动器同时运行同一安装目录。Windows Job Object 管理
服务端及其子进程，启动器进程关闭时也会关闭其拥有的作业。

“前往游戏”也通过 `hosting.destination` 核对具体启动标识，然后选择主页的服务器
和客户端构建。进程被替换、停止或出现故障时不能返回连接目标。请求期间切换配置
或离开页面，会停止其后续界面操作。状态轮询和日志只接受最新请求的响应，旧的
就绪状态不能覆盖后来出现的失败状态。托管页只选择连接；主页的单机入口刷新服务后继续启动所选客户端。

进程使用重定向的标准输入、输出和错误流，不显示控制台、不经过 shell 展开。
只有 stdout 中完整的 `FT_HOST_READY 1` 行才代表就绪，stderr、未结束的行和截断行
都不能触发。启动有超时限制。正常停止先发送 `stop` 并关闭输入，让服务端完成清理，
超时才终止自己拥有的进程组。服务端协议也要求收到输入 EOF 后退出。
意外退出、启动超时、日志失败和强制结束都会保留可见状态。

报告最终状态、释放程序包和存档锁之前，启动器会检查 Job 的活动进程数，终止仍存活的
受管子进程，最多等待十秒直到活动进程数归零。即使主服务端正常退出，只要需要结束残留
子进程，也会标记为强制停止。主进程意外退出时执行相同检查。若进程树验证失败，会报告
`process-failed`，并保留程序包和存档锁直到启动器退出，避免再次启动复用仍可能被占用的
文件。这项检查不保证与启动器无关的外部读取者已经释放文件。

启动器不对服务端、配置和诊断目录设置固定数量上限。适配器生成的配置文件、启动参数和
环境变量也没有启动器额外设置的数量或总字节数上限。文件必须保存在本次运行目录内；
重复文件名、Windows 设备名、日志文件冲突、空值和进程参数中的 NUL 字符仍会被拒绝。
环境变量名不区分大小写且不能重复。操作系统本身的进程和文件系统限制仍然适用，
启动失败会释放相关独占锁。生成的 YAML 放在启动器托管目录中，原服务端包配置不修改。

诊断输出保留资源边界：每行最多 4096 字符，界面保留 128 行，进程日志每份最多 2 MiB，
并保留一个轮转备份。适配器也限制服务端封包日志数量和大小，默认关闭完整抓包。

本机服务端运行期间不能重启更新启动器。服务端停止后，临时连接从服务器列表中移除，
不会转成永久远程服务器配置。重新启动前会使旧账号会话失效。

## 稳定存档目录

每次运行还会独占启动器数据根目录下的 `hosting/data/<配置标识>`，通过
`LocalServerContext.DataDirectory` 提供给游戏模块。该目录独立于程序包和轮转诊断日志。
配置改名、重启或更换更新后的服务端包，都保留同一路径；移除托管配置也不会删除存档。
目录记录所属游戏和客户端版本；同一标识被其他游戏或版本复用、元数据损坏、存在归属
不明的文件，或程序包、日志与存档目录相互重叠，都会在启动进程前报错。

存档锁独立于程序包锁，因此另一个进程不能通过选择第二份服务端包占用同一份存档。
存档目录没有固定数量上限。此目录约定本身不会启用持久化
提供者：本地存档模式在此目录内启用 SQLite，临时模式仍在停止后失去内存账号，
程序包模式仍使用包内配置的数据库。切换存储方式不会在提供者之间迁移数据。
备份存档目录前应先停止服务端。

## 验证与尚待接通的部分

隔离进程测试覆盖就绪、拒绝 stderr 标记、正常退出、启动失败和超时、强制结束、子进程
清理、目录锁、日志限制及过期启动标识。桥接测试覆盖临时服务器显示、编辑与删除限制和
启动器更新互斥。浅色和深色无界面浏览器检查覆盖页面、设置、房间地址、动画展开和确认框。

另有显式启用的集成测试，将完整 CN2013 发布包复制到隔离目录，通过后端桥接启动真实
服务端，验证六位密码注册与登录、拒绝错误密码、启动票据、本地管理页面、正常停止、
端口释放、重启、旧会话失效、临时账号消失、SQLite 账号保留及重启后拒绝错误密码，
配置改名与更换程序包后保留存档、不同配置之间数据隔离、删除配置后保留数据，
以及远程玩家与房主各自的连接地址。
新增两项本地存档测试先通过本机 HTTP 来源或 AList API 测试源流式下载完整包，经
`store.installServer` 安装，逐文件比较输入与安装结果的 SHA-256，再对安装出来的目录
执行相同的账号与重启验证。内容从磁盘流式发送，不用大容量内存字典保存完整服务端包。
AList 用例通过真实来源适配器请求协议测试源，不代表官方远程部署已经验收。
测试不打开启动器窗口或游戏，复制时排除本机覆盖配置和环境文件。PowerShell 运行方式：

```powershell
$env:FT_TEST_SERVER_PACKAGE = 'D:\\isolated-packages\\server'
dotnet test tests/FantasyTale.Launcher.Core.Tests -c Release --filter FullyQualifiedName~LocalServerPackageTests
```

另有 `ActualClientRetainsPlayerIdentityThroughOwnedServerRestart` 用例，通过当前启动器
后端启动真实国服 2013 客户端。使用空闲的测试客户端目录和完整服务端包显式启用：

```powershell
$env:FT_TEST_SERVER_PACKAGE = 'D:\\isolated-packages\\server'
$env:FT_TEST_CN406_CLIENT = 'D:\\test-clients\\CN2013'
$env:TEMP = 'D:\\test-temp'
$env:TMP = $env:TEMP
dotnet test tests/FantasyTale.Launcher.Core.Tests -c Release --filter FullyQualifiedName~ActualClientRetainsPlayerIdentity
```

测试只在复制的定义中启用本机托管，复制服务端包及原生运行时，注册新账号，等待认证插件
下载完成，并同时检查真实服务端玩家进入 MainMenu、启动器 Hook 已就绪。正常停止并重启
所托管的服务端后，再次登录和启动，要求仍为同一个持久化玩家身份。两次停止均检查原 EXE、
临时通信 DLL 的 SHA-256 恢复、永久认证插件的保留文件哈希、会话文件删除和服务端端口释放。模块正常的连接准备可能
修改测试客户端的 `login.ini`，测试不会恢复持久化的游戏设置。已做本地兼容处理的客户端
仅能证明该配置，不代表未经修改的原版客户端。必需插件通过配置的商店检查，不绕过验证。
未在 Windows 上同时提供这两个输入变量时，此用例明确跳过。

使用旧服务端包对照票据过期问题时，可将 `FT_TEST_LAUNCH_TICKET_SECONDS` 设为服务端支持的
正整数秒数。它仅修改复制的国服 2013 profile，保持认证启用，并将有效期覆盖值与启动、
登录成功时间记入验收记录。不设置则使用包自身的策略。失败清理先显式停止所拥有的客户端
和服务端，再执行后端等待退出的被动释放。

可将 `FT_TEST_CLIENT_HOLD_SECONDS` 设为正数，让两次成功登录后的客户端各停留指定秒数，
供独立查看实际画面。失败时保留隔离目录并报告路径；成功时清理隔离目录，并在测试输出中
打印不含凭据的验收记录。通过仅代表登录、Hook 就绪及重启前后账号身份一致；房间、实际
对局和物品变化仍需分别验收。

首页“单机游戏”始终只有一个入口。同游戏与版本的私有服务已就绪时直接复用，
不再重复弹出配置窗口或增加一项普通服务器。关闭账号认证时，发现与启动流程
均采用本地配置的昵称模式，不请求账号恢复、注册或登录。未登录也可以点击

自动连接。日志原位刷新并显示最新输出，不会因服务器状态刷新而重新回到顶部。
