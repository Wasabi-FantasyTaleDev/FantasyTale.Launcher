# 客户端诊断

[English](diagnostics.md)

## 启动器启动与退出

宿主把启动、前端就绪、窗口唤醒、关闭请求及已注册桥接方法的执行结果记录在本地：
`%LOCALAPPDATA%/FantasyTale/Launcher/host-lifecycle.jsonl`。显式使用 `--data-root`
时，日志放在指定的数据目录。当前文件上限为 64 KiB，只保留一个轮换文件
`host-lifecycle.jsonl.1`。这不需要启动游戏，也不需要启用客户端诊断插件。

记录包含 UTC 时间、进程编号、事件/方法名、异常类型或固定的关闭中结果代码。
不记录桥接参数、返回值、异常消息、账号、密码、令牌及票据，不会自动上传。
日志写入失败不影响窗口操作。排查另一台电脑的启动/退出问题时，请保留那台电脑
复现后的两个文件；正常电脑的日志不能说明另一台电脑的故障原因。

Gateway 连接诊断记录连接类型、本地监听端口和固定的生命周期事件，包括唯一性确认及关闭。
不记录远端地址、账号标识或协议内容。选服器与启动器各自限制最多 64 KiB 元数据，达到上限时
记录固定标记。重复的未知标准错误会脱敏并去重，避免耗尽连接事件的记录额度。磁盘仍只保留
两个各不超过 64 KiB 的日志文件；复制操作最多返回最近 512 条通过校验的启动记录。

## 游戏进程诊断

启动前在客户端插件列表启用**诊断模式**。此插件默认不选中。每次启动使用以本地启动时间命名的独立目录，
例如 `diag_20261103_044700`，启动器保留最近十个；含有启动器以外写入文件的目录保持原样且不再计数。
诊断按钮可打开该客户端的日志目录。

* `fthook.log` 记录插件加载结果，不记录登录账号和票据。
* `crash.log` 保存有大小上限的异常记录，包含上下文标志和段寄存器。
  首次严重异常还记录异常分派调用帧以及最多八个本地异常处理器。
  即使之前被处理的异常耗尽记录条数，也会在文件大小上限内保留首次严重异常。
  `stack_candidates` 只是栈内存中的地址匹配，不代表已经验证的调用链。
* `exception.dmp` 通过独立线程和系统转储库保存首次受支持的严重异常。
  转储库通过完整系统目录路径加载，避免复用游戏已加载的同名旧版库。
  默认上限为 32 MiB，可配置至 64 MiB；故障线程最多等待十秒。
  转储还请求保存主程序映像中可读取的内存页，最多占用同一大小上限的一半；完整文件仍受总上限约束。
  跳过受保护或未映射的页面；结果中的 `image-memory-complete`、`image-memory-partial`、
  `image-memory-not-captured` 分别说明运行时映像页面是否完整、部分或未被保存。
* `exception.dmp.status.txt` 保存转储初始化和写入结果，上限为 1 KiB。
  `written error=0` 表示最终文件保存成功；`failed-size-limit`、`failed-create`、
  `failed-write`、`failed-flush` 和 `failed-publish` 区分失败阶段，并附 Windows 错误码。
  记录停在 `armed` 表示尚未开始写入；停在 `writing` 不能证明已经完成。
  最终保存失败时保留临时文件和已有转储，不覆盖已有文件。
  系统写入器返回错误 87 时，会在相同大小上限内重试一次，省略异常流并保留进程和线程数据。
  `written-without-exception error=0` 表示这种后备快照保存成功；原始异常记录仍在 `crash.log` 中。
* `receive.ftnet` 记录主程序同步导入的 `recv` 和 `recvfrom` 接收数据。
  默认上限为 16 MiB，可配置至 64 MiB；每笔记录刷新到文件，便于故障后分析之前的数据。

转储可能来自随后被游戏处理的首次异常，不能直接等同于未处理的崩溃。
正常退出或外部强制结束进程不保证产生转储。接收记录是原始传输分片，并非已解码的游戏包；
不包含发送方向、异步接收、动态导入及其他 DLL 内的接收调用。
转储和接收记录可能包含游戏内存或流量中的账号数据，应在本地保管并检查后再分享。

FTNET 文件以 ASCII `FTNET` 和版本字节 1 开头。每笔记录使用 24 字节的小端头部：
tick u64、socket u32、原始长度 u32、记录长度 u32、flags u32，随后为最多 64 KiB 的数据。
受控测试已验证访问违规转储及本地回环接收记录。独立写入器测试还覆盖大小上限、
写入失败、已有临时／最终文件和结果文件上限。真实游戏仍需单独验收。

进程测试覆盖诊断插件当前声明的全部兼容标识：`kr-812`、`cn-279`、`cn-324`、`cn-406`、
`cn-706`、`cn-717`、`id-400`、`id-1809` 和 `kr-1256`。测试使用真实运行时和诊断 DLL
启动受控原生程序，接收本地回环数据后主动触发访问违规；每项检查转储异常流、写入结果、
接收内容、原 DLL 恢复及 `session.toml` 删除。这些标识用于验证插件选择和会话标注，
测试程序并不复现各版本真实游戏的接收导入、异常处理或图形生命周期。
