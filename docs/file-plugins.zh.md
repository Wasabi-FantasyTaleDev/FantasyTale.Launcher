# 文件替换插件

[English](file-plugins.md)

`kind = "files"` 插件由启动器执行，不在游戏进程中运行。它可以替换独立 UI 资源、完整资源归档、字体或辅助 DLL，无须注入插件 DLL。目前不修改 BFZ/PKN 内部条目，需要提供完整的替换文件。

每个 `[[files]]` 条目声明相对路径 `source`、`target`、准确的 `size`、小写 `sha256` 和可选的 `builds`。路径使用正斜杠，允许子目录和 Unicode 文件名。空选择器列表适用于所有兼容版本；其他选择器使用版本 ID、`branch:<名称>` 或 `*`。越界路径、链接、设备名以及启动器会话和恢复文件均被拒绝。文件插件不能包含原生入口。Launcher 0.1.57 和 FtHook 3.7.2 起，可以声明由内存补丁 `when` 引用的布尔选项；这些选项不影响文件部署，未被引用或非布尔类型的文件插件选项会被拒绝。Launcher 0.1.54 和 FtHook 3.7.1 起，同一文件包还可携带按版本限定的内存补丁，沿用现有的签名、原始字节和回滚契约。只有匹配版本会启用原生补丁加载；其余版本沿用原来的文件部署流程。

启动前检查文件内容，将替换文件与原生运行库放入同一个持久事务。目标冲突，包括文件与父目录冲突，会阻止准备。资源替换、原生组件与备份不再设定固定文件数或字节上限；声明大小、SHA-256 校验和事务归属检查仍为必需。默认在确认退出后恢复原文件，并移除新增文件。文件插件可声明 `[plugin] restore_files = false`（需要启动器 0.1.15 或更新版本）：目标文件的大小和 SHA-256 已与当前组件一致时不重复写入；整组替换成功后永久保留，正常退出或恢复已停止客户端时均不还原。替换尚未完成时仍回滚整组文件。原生 Hook 运行库始终使用临时部署。外部修改会使日志和备份保留，等待明确恢复。新建的空目录可能保留。

普通资源包复用文件夹／ZIP 导入及商店下载流程。导入不会自动启用。启用和版本要求由游戏／客户端的 `client_policy_rules` 管理。所有包均拒绝 `required_on`、`warn_on`、`require_latest`，包括内置和商店包。`require` 规则不能关闭；带本地化 `warning` 文字的推荐包在安装后保留关闭启动确认，并保留用户的明确关闭选择。来源归属仍由 `game.plugin_sources` 和包的 `update_source` 声明。取消和 Escape 不会授权启动。后端在获取登录凭据前检查插件 ID／版本确认，启动服务持有客户端锁后再次检查。

## 国服认证组件

`bubblefighter.fantasy.login-fix-cn` 从商店下载，仅对 `branch:cn` 生效。来源由 `game.plugin_sources` 声明；必选和最新版本规则在 `client_policy_rules` 中逐个列出国服客户端，不随启动器附带插件文件。安装客户端时作为必选组件提供；启动前必须存在已安装、已启用的选择。它替换 `GPKitClt.dll`，并且只替换一个认证文件：

| 版本 | 认证模块目标 |
| --- | --- |
| cn-279、cn-324 | GameWidget.dll |
| cn-404、cn-406、cn-706、cn-717、cn-735 | sdologinentry.dll |

两个名称都使用现有的登录票据转交桥接库。插件负责的目标不再由游戏模块重复部署，即使用户明确关闭组件也一样。按本次要求，此组件使用关闭后的启动确认策略，而非不可关闭的开关锁定。缺少包定义或启用的文件校验失败，仍会阻止启动。

GPK 替代组件和登录转发库从启动器源码构建，由 `tools/package-native.ps1` 打包，并重新生成文件大小和哈希。不分发游戏原版 DLL。后续认证 Hook 沿用本组件标识；当前文件插件契约不加载额外 Hook。为未验证客户端声明文件，不代表其启动或登录适配已经验收。

## 强制安装与最新版本

安装提示中的必选推荐组件始终勾选并锁定；即使默认已启用也会显示一次。确认后启用，取消不允许继续本次启动。确认记录按客户端和类型化推荐规则保存在 `client-policy.seen` 中。之后手动关闭组件时，沿用上文的每次启动警告。

游戏／客户端的 `client_policy_rules` 中 `type = "latest"` 表示启用的组件需从 `update_source` 指定的商店来源 ID 发现最高兼容 SemVer 版本，未指定时使用原安装来源记录。检查在界面就绪前开始，复用商店目录的首次请求。开启插件自动更新时，在后台校验、下载并为未运行的客户端应用更新。启动游戏只读取已知更新状态，不刷新来源，也不等待检查。尚未应用的必选插件更新以卡片展示当前版本、新版本和实时下载进度；用户可以取消、等待应用后继续，或明确确认使用完整的已安装版本启动。来源读取失败不会阻止启动；缺失或损坏的必选插件仍由本地校验拒绝。本次确认仅授权当前显示的版本。

国服认证组件已启用此策略，来源绑定为 `fantasy-tale`。插件更新不能改变配置中的类型化规则、来源归属或文件保留策略。同名本地导入仍被拒绝。认证组件 1.0.1 在包内 `file-install.toml` 声明 `schema = 1` 和 `restore_files = false`。独立策略文件随商店快照校验，保留旧启动器对主清单的读取能力，使其能提示需要 `minimum_launcher_version = "0.1.15"`，而不会报未知字段。策略文件只允许这两个键，与主清单声明冲突时拒绝加载。该组件的行为为：GPK 与当前版本对应的认证库在退出后保留。关闭组件只停止后续部署，不会卸载已经永久替换的文件。不进行原生代码热加载。
