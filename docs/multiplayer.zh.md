# 联机目录

[English](multiplayer.md)

联机通过同一份目录契约展示长期服务器和临时房间。商店来源可使用配置好的 AList、
HTTP 或 GitHub 传输提供长期服务器，实时目录还可以发布有租约的房间。
目录本身不负责组网通道，也不运行游戏进程。

## 启动器使用流程

Launcher 0.1.38 内置 Gateway，可在游戏界面选择目录提供的独立 IPv4 服务器端点。
认证仍使用目录的实际认证端点，游戏连接则交给本地 Gateway。指向同一端点的自动、
手动选项会明确拒绝，待原生选择桥完成后再启用。本版尚未完成六项选服及所有客户端的
游戏界面验收。

此页面会记住上次选择的是“联机房间”还是“服务器”，再次进入时恢复该选择；
如果链接明确指定选项卡，则以链接为准。公开房间功能尚未开放时仍可浏览联机房间页，
连接范围列表中的“公开房间 - 将在后续版本开放”显示为灰色，不影响仅本机和局域网使用。

内置服务器的独立 TOML profile 可通过 `icon_asset` 指定网页资源内的图标，
其他服务器继续使用自己提供的图标或默认图标。
收藏后显示黄色实心星，文字淡入淡出切换，按钮宽度保持不变。

原来的独立“服务器”页面已经弃用，后续不再维护。已有服务器的管理功能已经合并到“联机”的“服务器”标签中。旧的 `/servers` 地址仍会保留，并自动跳转到这个标签，方便旧书签继续使用。已添加的服务器、目录发现的服务器和临时房间共用同一个固定工作区；浏览已添加服务器时不会立即切换主页的账号或目标，只有点击“选择服务器”后才会切换。

打开“联机”，选择来源，在“联机房间”和“服务器”之间切换。商店来源和实时目录
使用相同的长期服务器发现界面。浏览、查看详情和收藏都不会下载服务器 profile，
也不会加入已保存服务器。只有明确选择或保存时，才通过来源对应的传输下载其 TOML
profile 并导入本地；仅提供内联信息的目录条目会在此时转换为同一种 profile。

选中支持的客户端版本，在主页使用该服务器。缺少客户端时下载客户端，需要登录时登录，
继续沿用主页主按钮流程。选择目录不会提供账号，也不会绕过登录要求。
账号目标包含来源地址与条目标识，不同房间不会误用同一个账号会话。

### 保存身份与配置文件交换

新增服务器可以选填“服务器 ID”。留空时按游戏服务器的地址与端口生成；没有配置游戏
地址时，使用 API 的主机名和有效端口。ID 只允许 ASCII 英文字母、数字、`-` 和 `_`；
自动生成时会将地址中的其他字符替换为 `_`。例如 `127.0.0.1:8080` 生成
`127_0_0_1_8080`，保存为 `servers/127_0_0_1_8080.toml`。
系统保留设备文件名不可使用；新增 ID 重复检查不区分大小写。

连接地址改变时，稳定 ID 保持不变。读取和更新使用文件内部的 `server.id`，
用户手动改文件名仍能识别。内置服务器的 ID 为 `FantasyTale`，文件为 `FantasyTale.toml`。

添加和编辑弹窗的“服务器信息”页底部提供“导入配置”和“导出配置”，格式都是 TOML。
导出使用已经保存的配置，不包含账号凭据。导入优先匹配稳定 ID，再匹配相同游戏的连接
目标。内容一致时复用且不重写；内容不同时需要用户确认覆盖，确认仅对刚才检查的已保存
内容生效，期间发生其他编辑就必须重新检查。取消不会改变原配置。

本地 profile 仍作为 `/v1/catalog` 所返回展示信息的回退。网络接口使用 JSON，
由 .NET 后端读取和写入 TOML，浏览器无需解析 TOML。实时展示信息只覆盖 JSON 中
实际提供的字段。例如，仅更新在线人数不会重置本地关闭的在线名单、白名单标记、
介绍或图片。介绍和图片按语言标签合并，标签不区分大小写。

明确提供的值优先生效：`rosterEnabled = false` 隐藏在线名单，`onlinePlayers = -1`
隐藏该人数，`playerLimit = null` 表示人数不限，`images = []` 清空默认图片列表。
人数为 null 表示未知。未提供的字段保留本地回退值；无效远程数据会被拒绝，不替换
上次验证成功的目录。这一覆盖复用原有目录请求，不会自动改写已保存的 TOML 或连接地址。
服务器信息页提供“从服务器更新”，用户主动点击后会原子保存最新验证过的名称、介绍、
支持版本和插件声明，同时保留稳定 ID 与连接地址。服务器主动要求迁移地址仍需要单独的
确认流程。

加入的房间始终是临时连接。离开页面后，后端仍检查成员记录，进行账号请求或启动游戏前
还会再次确认。房间消失或连接信息改变会使旧账号会话失效。目录无法连接时，已确认的
房间在租约过期后隐藏。经审核的长期服务器则加入用户的普通服务器列表。

读取已加入房间列表或加入其他房间时，会立即清理到期记录及对应账号会话。
解析已到期记录会在请求目录前失败，需要重新加入。清理不等待延迟的后台目录请求。

后台每轮按来源合并读取，同一来源中的已加入房间共用一次目录读取，最多同时读取四个来源。
慢来源不会阻塞其他正在读取的来源。某个来源返回无效数据时，只影响该来源本轮检查，
后续仍会继续刷新。客户端不再限制已加入房间数、保留的发布状态数、已知来源数、目录条目数
或响应字节数。目录 JSON 直接从响应流解析，格式、标识、重复条目和房间租约仍会校验。
独立部署的目录服务仍可能执行其自身的部署策略。

重新加入房间时，即使地址和标识没有改变，也会建立新的一次连接。之前加入时发起的目录
请求不能删除新连接，也不能让新连接的账号会话失效。

“提交服务器”将名称、API 地址、介绍及支持版本送入所选来源的审核队列，不会直接公开。

房主在“本地服务端”选择房间模式并启动服务端。进程报告就绪后，才可以点击“发布房间”，
选择来源并填写可选介绍。心跳在后端运行，与当前页面无关。正常停止服务端会撤下房间，
异常退出也会被检测。“取消发布”保留正在运行的本地服务端。编辑使用中的目录来源前，
需要先取消其房间发布。

标题、来源控制和加入操作保持可见，列表与介绍分别在容器内滚动。弹窗、下拉及过渡动画
复用现有控件，支持浅色、深色和七种界面语言。

## 自建目录 API

独立的 `FantasyTale.Launcher.Directory` 程序无需启动器、游戏、商店或游戏服务端即可运行。
按目标平台发布：

```sh
dotnet publish src/FantasyTale.Launcher.Directory -c Release -r linux-x64 --self-contained false -o directory-publish
```

安装 .NET 10 ASP.NET 运行时。配置从 `FT_DIRECTORY_` 前缀的环境变量或对应命令行参数读取：

| 设置 | 默认值 | 用途 |
| --- | --- | --- |
| `Listen` | `http://127.0.0.1:8096` | 监听地址，可在前方部署反向代理 |
| `DataPath` | `directory-data` | 已审核服务器与待审核记录目录 |
| `Name` | `Fantasy Tale` | 来源显示名称 |
| `AdminToken` | 必填 | 来源管理员审核用私有令牌，16–256 字符 |
| `MaximumEntries` | 512 | 服务器、待审核记录和房间分别计数，上限 1024 |
| `RoomLeaseSeconds` | 90 | 心跳租约，可设置为 30–300 秒 |
| `HostPolicy` | `auto` | `ip`、`domain` 或 `auto`，遵循启动器网络策略 |
| `Region` | 未指定 | 可选的两个字母部署地区代码 |
| `ReadRequestsPerMinute` | 1200 | 全局读取请求额度 |
| `WriteRequestsPerMinute` | 120 | 新发布、提交和审核请求额度 |
| `LeaseRequestsPerMinute` | 8192 | 独立的心跳与撤下请求额度 |

例如通过部署配置设置 `FT_DIRECTORY_AdminToken`，运行 `dotnet FantasyTale.Launcher.Directory.dll`。
这只是私有管理接口的普通凭据，不涉及发布签名或公钥流程。目录服务不会主动连接提交的
地址；玩家选择目标时，由启动器验证目标的实际接口。

API 地址下提供：

| 方法与路径 | 行为 |
| --- | --- |
| `GET v1/info` | 协议版本、来源名称、房间租期和网络策略 |
| `GET v1/entries` | 已审核服务器与未过期房间，不含私有管理令牌 |
| `POST v1/submissions` | 提交长期服务器等待审核 |
| `POST v1/rooms` | 发布临时房间并返回私有租约 |
| `POST v1/rooms/{id}/heartbeat` | 使用该房间的令牌续期 |
| `DELETE v1/rooms/{id}` | 使用该房间的令牌撤下 |
| `GET v1/admin/submissions` | 使用管理员令牌读取审核队列 |
| `POST v1/admin/submissions/{id}/approve` | 通过指定待审核版本 |
| `POST v1/admin/submissions/{id}/reject` | 拒绝指定待审核版本 |
| `DELETE v1/admin/servers/{id}` | 移除已经审核的服务器 |

发布内容包括 `game`、`name`、`apiUrl`、`builds` 和 `description`；目录条目额外包含 `id`、
`kind`（`server` 或 `room`）和 `expiresAt`。接口不依赖具体游戏，自建服务可以实现同一协议。
管理员接口要求 `Authorization: Bearer <管理员令牌>`。房间令牌只能续期或撤下自己的房间，
不能执行审核。

## 容器部署

将 `src/FantasyTale.Launcher.Directory` 发布为不含运行时的 `linux-x64` 程序，输出到
`deploy/directory/publish`，连同 Dockerfile 和 Compose 配置一起复制到服务器。将
`.env.example` 复制为 `.env`，设置私有管理员令牌，再运行 `docker compose up -d --build`。
默认端口为 8096。未指定地区时 `FT_DIRECTORY_REGION` 可留空；明确指定时使用两个大写字母。
`FT_DIRECTORY_HOST_POLICY` 支持 `auto`、`ip` 和 `domain`，通过发现接口告知客户端。

容器使用普通用户、只读根文件系统、持久化数据卷、有上限的日志及 256 MiB 内存限制。
更新时保留数据卷。`.env` 不进入版本控制，也不要随客户端定义发布。这些部署文件只运行
目录服务，独立于已经运行的游戏服务。

## 生命周期与限制

已审核服务器和待审核记录通过独占文件锁、原子替换及确认前落盘保存。写入失败不会改变
可见状态，损坏文件会阻止启动而不会悄悄重置。房间租约只保存在进程内，目录重启后消失，
房主可重新发布。过期的房间标识无法续期，重新发布会产生新标识，旧命令不能撤下新房间。

每个发布的房间独立管理一个正在执行的后台操作，最多四个后台操作同时请求目录服务。
一个房间请求卡住时，不会阻塞其他房间后续续租或进程退出后的撤下。
手动撤下与同一房间的续租共享操作锁；关闭时先取消并等待正在执行的操作结束，再执行最终撤下。

默认每 30 秒发送心跳。网络失败会显示并重试，直到已确认的租约过期。撤下失败会停止续期，
后台继续重试，最终按租约过期消失。发布成功但 HTTP 响应丢失时，未确认的记录同样因没有
续期而过期。启动器最多保留 32 条发布状态和 32 个已加入房间，同时最多运行两个本地服务端。
房间私有令牌仅保存在后端内存，不传入前端。

启动器退出时，所有房间撤下请求共用一个十秒期限，同时最多发送四个请求。
目录源不可访问时，不会因每条发布记录分别等待完整超时而拖延本机服务端清理。
未确认撤下的房间保留原租约的到期时间，启动器不会把它们报告为撤下成功。

请求体上限 16 KiB，单条发布内容 8 KiB，持久化文件 8 MiB，同时连接数 64。客户端和服务端
均验证元数据，拒绝 HTTP 重定向。写入前使用不含凭据的发现请求取得来源明确指定的 IP 或
域名访问策略。

## 服务器插件策略

目录和账号响应携带 `clientPolicy`。其中 `sources` 是服务器建议玩家添加的商店目录，`plugins` 为每个插件身份
列出类型化规则。每条规则包含 `id`、`type` 和 `builds`；`builds` 为空表示所有客户端版本。

| 类型 | 额外字段 | 连接此服务器启动时的效果 |
| --- | --- | --- |
| `require` | 无 | 插件必须已安装并启用；启动器会提供安装。 |
| `disable` | 无 | 仅本次启动关闭插件，不改变已保存的选择。 |
| `recommend` | `sources` | 每个客户端、每条规则推荐一次，从指定来源安装（为空时可用任何已添加的商店）。 |
| `min_version` | `version` | 已启用的插件低于此版本时，启动前更新。 |
| `max_version` | `version` | 已启用的插件高于此版本时，切换到允许的最高版本。 |
| `latest` | 无 | 启动前把已启用的插件更新到最新版本。 |

同一插件中适用版本重叠的规则不得冲突：同类型的两条规则、`disable` 与其他任何规则、`latest` 与
`max_version`，或最低版本高于最高版本。元数据读取器会在选择客户端之前拒绝冲突、未知或格式错误的策略，
也会拒绝包含本启动器不认识的分区或字段的策略。客户端版本本身要求的插件不能被禁用，此时拒绝启动。

安装和版本切换只使用玩家已添加的商店。服务器的来源显示在其页面上，并带有“添加”按钮；服务器不会自行
添加商店。本地保存及商店下发的 profile 以扁平的 TOML 表保存策略：

```toml
[[client_policy_sources]]
name = "community"
kind = "http"
base_url = "https://plugins.example/"
catalog_path = "source.toml"

[[client_policy_rules]]
plugin = "bubblefighter.fantasy.cn-auth"
id = "need"
type = "require"
builds = ["cn-404"]
```

## 验证与剩余工作

测试覆盖审核可见性与持久化、元数据隔离、容量限制、写入失败、独占存储、私有房间令牌、
过期及错误或过时所有者、真实 HTTP 双端调用、来源间目标隔离、畸形输入、拒绝重定向、
后台心跳及进程退出后的撤下。完整 CN2013 本地服务端包还验证了发现、加入、真实账号登录，
以及撤下后的账号失效；没有启动 Launcher 窗口或游戏。浅色和深色无界面检查覆盖固定页面、
来源与提交弹窗、加入、发布和取消发布控件。

内置 Bubble Fighter Fantasy 目录现已部署，地址为 `http://bf.600819.xyz:8096/`。
已使用启动器的共用网络客户端验证不含凭据的初始发现、IP 回退，以及后续遵循来源明确
下发的 IP 策略。定义保留域名，后续 DNS 迁移无需修改代码。旧的内置空地址配置会继承
此地址，同时保留启停选择、自定义名称及明确填写的替代地址。公开目录初始为空。
部署验证覆盖外网发现与列表、拒绝未授权管理请求及重启恢复，没有发布测试房间。

真实远程玩家验收及来源管理员的图形化审核界面仍未完成。本地持久化存档和
自动安装服务端包是另外的核心工作。当前使用明确的直连地址，自动防火墙、NAT 或 VPN 设置
尚不在实现范围；成功发布到目录不代表好友一定能够访问房主公布的地址。
