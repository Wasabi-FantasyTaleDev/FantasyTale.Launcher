# 原生绘制分析

截图只用于视觉参考，不能直接决定逻辑尺寸或控件坐标。截图裁剪、Windows DPI、浏览器缩放、游戏渲染缩放应分别处理。

两版 Ui/UiScheme.ini 的标题均为 NexonBTBold、字号 14、字重 400。v1 装饰为 1，装饰色 0xff888888；v2 装饰为 4，装饰色 0xff3a85cb。cn-717 中装饰 1 不进入描边分支。字体名含 Bold 并不表示应使用 CSS 700。

cn-717 Config/Fonts_cn.csv 将 Default、DefaultBold、NexonBTBold 映射至 GB13000.ttf，Malgun 映射至 DF_GB_Y9.ttf。标题已使用配置指定的 GB 字体；部分手工组合的正文仍使用 Malgun 近似，需要逐控件查证。

cn-717 sub_BAE810 将字号限制为至少 11；sub_C5ACD0 以 size << 6 设置字体尺寸。列表行高里的 4/3 公式不足以证明所有字号都要乘以 4/3。

cn-717 sub_B82770 和 sub_B828B0 分别接收矩形或位置加尺寸，最终进入 sub_BB0440。后者缓存文字纹理，再按纹理尺寸使用整数除法对齐：标志 1/2 为水平居中/靠右，4/8 为垂直居中/底部，0x10 为换行。文字纹理随后还经过独立的游戏渲染缩放。

cn-717 sub_BAEAC0 生成文字纹理；sub_BAD380 获取字形、生成位图，并将灰度覆盖率合成到 BGRA 纹理，因此原生路径支持抗锯齿。字形纵坐标包含字号减一和字形 bearing。700 字重扩张与装饰描边是不同操作。

cn-717 sub_BAE810 通过 sub_C61AE0 设置 32、128 的轮廓扩张参数，在 26.6 表示下为 0.5 和 2。当前浏览器以 2 像素 stroke 近似 v2 标题装饰；其轮廓几何不能视为与原生完全相同。sub_BAD8F0 的文字测量也包含装饰：装饰 3 的宽/高增加 1/2，装饰 2/4 增加 2/4。

已确认坐标：cn-717 sub_B46F20 在内容原点下使用 (3-marginLeft, 9-marginTop)，换算到外框为 (3,9)，按外框宽度水平居中，不进行垂直居中。Title_Margin_Top=38 是内容边距，不是标题 Y。v2 标题已按此实现，移除经验性基线偏移。cn-717 sub_B6C9E0 在分组局部坐标 (26,4) 绘制分组标题，格式标志为 0；scheme 默认字号为 12，但选项表单明确覆盖为 13；选项分组使用 13 及顶部对齐。

cn-279 sub_4A7550 已独立确认标题外框坐标为 (37,11)，格式为 0（左对齐）。两版标题坐标分别实现。

当前 Canvas 的 4 倍采样只是浏览器平滑近似，不是查证的原生采样倍率。浏览器 hinting、字宽、描边几何、位图边界仍可能不同；文字纹理高度使用浏览器 descent 近似原生位图指标。滑条刻度和部分房间模式布局仍包含截图校准值，尚未全部追到运行时函数。原始 .ui 转换保留属性，但尚不支持全部控件、运行时可见性及控制器修改。

## 消息框的运行时自适应

消息框的 `.ui` 文件提供的是初始模板尺寸，不是所有正文情况下的最终外框。cn-717 `sub_921AB0` 在布局阶段先读取正文纹理尺寸：正文宽度按至少 200 个逻辑单位处理，正文高度按“测量高度加 16”处理；随后将其与图标区域和按钮区域比较，重新设置外框、FrameBox 和子控件的位置。单按钮模式把按钮水平居中，双按钮模式根据按钮宽度和间距从右侧排列。cn-279 `sub_8A27D0` 使用同一组计算，常量地址不同，不能把 cn-717 地址当作 v1 的证据。

Web 公告因此保留 v1/v2 manifest 的最小尺寸和字体矩形，在正文测量结果超过模板时扩展内容区；FrameBox 高度、图标垂直位置、正文矩形和按钮 Y 坐标跟随扩展后的结果。公告使用官方单按钮模式，只创建居中的确认按钮；确认框仍使用各版本自己的双按钮布局。正文没有为了塞入固定高度而额外压缩行距或添加换行。

公告、确认、警告和错误共用 `DlgMessageBox.ui`。两个版本都定义了同一组图标数组：索引 0 为 `Images/Ui/MsgBoxIconNotice.png`（63×58），索引 1 的警告项保留 100×58 的布局槽位但原始 PNG 实际为 63×58，索引 2 为 `MsgBoxIconQuestion.png`（63×58），索引 3 为 `MsgBoxIconError.png`（63×58）。运行时只切换图标数组项和按钮模式，窗口、FrameBox、正文测量仍走同一套布局；绘制时按 PNG 原始尺寸显示，不能把警告图标拉伸到 100 像素。

库中的 `dialog` 现在接受布尔快捷形式或配置对象。配置对象可提供 `icon`、`title`、`text` 和 `buttons` 数组；按钮数组由同一个 renderer 按原始 sprite、尺寸和版本间距绘制，默认确认框只是两个按钮的配置，公告只是一个按钮的配置。配置 `body` 回调后，可以在同一套外框、标题、内容原点和按钮布局中绘制任意控件树，不需要再复制一套窗口。Vue 组件库导出通用的 `BfDialog`，`BfMessageBox` 只是兼容包装层。

素材位置记录于 assets-v1.tsv、assets-v2.tsv，包含原始成员路径、来源归档、SMF SHA-256、帧序号、含端点矩形。关闭按钮为 Images/Ui/DialogButtonClose.smf；v1 确认/取消为 DialogButtonOk/Cancel 的 Up、Down、Hover、Disabled 分图；v2 为 Images/Ui/DialogBtnOk.smf、DialogBtnCancel.smf；tab 为 Images/TaskBar/Option/OptionTab01/02.smf；外框为 Images/Ui/DialogSkin-Basic.smf。拉伸前须逐帧裁切，避免 atlas 间隔渗色。

完整函数链及具体限制见配套英文 rendering.md。


关闭按钮位置已按独立证据修正：cn-279 sub_4A7170 的内容局部 X 为内容宽减按钮宽减 5，Y 为 11 减标题上边距；cn-717 sub_B469E0 的 X 为内容宽减按钮宽加 3，Y 为 8 减标题上边距。换算到外框，v1 的右边距为 15、顶部 11，v2 的右边距为 7、顶部 8。原 SMF 含端点矩形给出 v1 17×17、v2 21×21，直接使用原尺寸及 Up/Down/Hover 帧。

窗口边距不是额外的 CSS 留白：原生内容区在外框内偏移 (10,38)，外框宽高分别为内容宽+20、内容高+50。cn-279 sub_4A7550 明确将四边距加到绘制尺寸；cn-279 sub_4A0650 将父内容原点传给子控件。选项页采用 DlgOption.ui（294×270）及 DlgOption2.ui（300×310），外框为 314×320 和 320×360。cn-717 sub_6EFA30 在 0x6F00DF 加载 Ui/DlgOption2.ui；同一函数包含其他布局分支，本演示只实现该资源布局，不声称覆盖所有运行时选项变体。tab、内面板和底部按钮直接读取对应根布局的坐标，加内容原点；不再按截图做偏移。


## 滑条、创建房间按钮与缩放合成

cn-717 `sub_B62940` 使用 `(width - 41) / (max - min)` 计算步长，以 `(max - min + 1) % interval == 1` 校验刻度间隔，滑块位置为 `truncate(15 + step * (position - min))`。客户端二进制 `0xEBF7E0` 的 double 常量已确认是 15。`sub_B62D80` 在 x=15..width-15 内绘制轨道，刻度位于 `truncate(20 + interval * step * i)`，完整带留白素材的纵坐标是 height-35。cn-279 `sub_4B66B0` 也独立确认了刻度素材绘制。`Images/Ui/TrackBar.smf` 的 6/7 帧是禁用/启用刻度，尺寸 1x31；3/4/5 帧是正常/悬停/禁用滑块，尺寸 12x31。目前交互滑条绘制启用正常态，禁用与悬停状态的完整一致性尚待实现。最小/最大文字使用 scheme 字体、format 37 居中及原始文字矩形。选项里的 178x55 控件保留原尺寸，不再把控件宽度替换成轨道宽度。

创建房间模式按钮位于 `Images/DlgCreateRoom/BTN_*.smf`，正常帧为 190x51，现在保留该尺寸，不再压缩为 183x43。v1 的模式列表来自自己的表单。运行时模式排序和条件选项显隐仍是重建预览，尚未完整移植房间逻辑。复合 checkbox 文字从 x=30、y=1 开始，对应 cn-717 `sub_B6AF90` 的默认素材宽度约定，采用原生度量近似的居中文字矩形。

九宫格皮肤先在一个逻辑尺寸 Canvas 中按共享整数边界合成，再由宿主统一缩放，消除独立 DOM 素材块舍入造成的非整数缩放空隙。这不代表与游戏 GPU 采样完全相同。原始裁剪素材及 SMF 路径仍保留在 manifest 与素材来源表中。

## 共用库与自定义页面

`createGameUi({theme:'v1'|'v2'|'v3',resourceRoot:'./local/'})` 提供 `windowShell`、`panel`、`label`、`checkbox`、`groupBox`、`trackBar`、`button`、`renderNode` 及示例页面。`groupBox`、`trackBar` 接受原始 XML 风格属性名。`customSettings()` 使用这些基础控件创建新的中文 overlay 设置窗口，在预览中选择“自定义设置”即可查看。数值变更通过 `bf-change` 发出，按钮通过 `bf-action` 发出。设置持久化由 overlay 宿主处理，示例不保存设置。

执行 `node tools/game-ui-lab/native-layout.test.mjs` 可验证原始选项滑条坐标、端点限制、刻度数量及非法尺寸拒绝。Canvas 字体光栅化仍是浏览器近似实现，字体及字重 400 使用原资源证据。

自定义设置页保留原版选项分组的 `SpriteSetBackground` 属性，不再错误查找 `SkinSpriteSet`。原版选项分组宽度为 287；扩展设置使用更宽的共用自定义内容区，保留 13 单位主文字，以及选项页的独立 checkbox/文字矩形布局。

通用对话框的 v1 多按钮组按 cn-279 `sub_8A27D0` 从内容区右侧排列，按钮间距为 8（`dword_AA55E8`），外侧另有 scheme 提供的 10 单位右边距。自定义设置不再把外框坐标当作内容区局部坐标传入：300 宽的内容区中，两个 68 宽的按钮位于 156 和 232，距离 320 宽外框的右边缘为 10。v2 保留按钮组居中。


## 扩展设置、底部边界与字体继承

内面板位于 (3,27)、宽 344，分组再内缩 5，按钮位于 y=260。外框宽 370，
内面板距外框左右各 13，分组左右各 18。这些是沿用选项页嵌套关系设计的
自定义页面尺寸，不是声称原版三套选项页具有相同宽度。

外框高度包含内容底部与按钮底部的最大值，再加标题/内容原点和底部边距。
v1/v2 顶部边距 38、底部 12；v3 顶部 42、底部 12。按钮采用各主题原尺寸，
v1 多按钮居右、外侧保留 10，v2/v3 按钮组居中。显式外框高度作为下限，
不能使按钮越出外框。

不是通用 `GroupBox.smf`。cn-717 `sub_B6C9E0` 的标题坐标为 (26,4)，format 0，
